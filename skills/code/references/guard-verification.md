# Guard verification — a clean verdict needs two REDs

**A guard that cannot distinguish "nothing matched" from "nothing was read" reports a false clean.** The rule above scopes the ambiguity to a primitive a claim caller consumes; a guard's own input carries it too — an absent root, an unparsable corpus, an unresolvable scope, a lane whose red is swallowed before the gate reads it. Each makes an empty result indistinguishable from a passing one, so the guard exits 0 having verified nothing, and a backstop that logs the problem and then permits trains its readers to ignore it. A guard therefore fails CLOSED on input it could not read, and reports the cause instead of a verdict. Proving that takes **two** REDs, not one: revert the production change and confirm the guard detects the violation, then withhold its input and confirm it refuses rather than passes. A guard carrying only the first RED has a clean verdict nobody has ever falsified — and reading the code is not the second proof.
