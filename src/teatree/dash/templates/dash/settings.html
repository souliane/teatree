Settings

Everything this box is configured to do: the resolved model / credential / self-repair readouts below, then every config key from the schema. Sections are on the left, the selected section's grid on the right — one section is fetched at a time, so the page stays small. One row per setting, with the shipped default and then every scope side by side: global first, then one column per overlay. A cell reads green while it still equals the default and brown once someone has changed it; the count beside each section in the nav is how many of its settings have been changed, counting each setting once however many scopes override it.

Editing is in place and there is no save button — pick a value or type one and it is written as you leave the cell. Emptying a cell deletes that scope's row, so the setting resolves its default again. An invalid value is refused and the cell says why rather than keeping the text that failed. Hover a setting's name for what it does, and a cell for which tier of the resolution chain supplied it (env → DB overlay scope → DB global scope → overlay code default → shipped file). A secret value is never shown (***) and its input is write-only.

Compare instances puts this box beside every peer in the peer_instances registry — and beside any snapshot file loaded there — and shows what actually differs. Download this box's snapshot to keep today's capture as a record, or to carry it to a box no tunnel reaches; it carries no raw secret.
