# hooks — local conventions

See the root [`CLAUDE.md`](../CLAUDE.md) for the code-quality bar. This file adds only what is specific to `hooks/`.

## Default-allow — a gate refuses four things, and nothing else

Developing teatree, and the factory built out of it, is ALLOWED BY DEFAULT. Editing, testing, committing, pushing, merging, running the `t3` CLI, provisioning worktrees, refreshing a local database, dispatching agents — none of that is a gate's business. **A gate that refuses ordinary development work is a defect to fix here, not a rule to obey**: take the per-call escape or the kill-switch from § "Escape markers & kill-switches", finish the work, then fix the gate.

A gate refuses on its own authority in exactly these four cases.

| Refused class | What it covers | Enforced by |
|---|---|---|
| **Secret / credential egress** | a credential VALUE reaching a command line, a file, a commit, or the transcript. A `pass`/vault PATH is fine; its contents never are. | `handle_block_secret_file_print` |
| **Public-surface leak** | a private term, the operator's own words, or an agent signature reaching a public repo or forge post. **Fail-CLOSED always** — never routed through `_fail_open_or_deny`, never reading `danger_gate_fail_open`, never grantable by `[fp-confirmed:]`, because relaxing a leak block is a privacy regression rather than a lockout rescue. | `handle_banned_terms_pretool`, `handle_quote_scanner_pretool`, `handle_dispatch_prompt_quote_scanner`, `handle_block_verbatim_operator_paste`, `handle_block_ai_signature` |
| **Destroying work** | another agent's or person's work, or the shared base every worktree branches from — a whole-tree `git add`, a main-clone working-tree mutation, a blind overwrite of a config the operator edited on disk, disposing of a checkout that is live. | `handle_block_git_add_all`, `handle_block_main_clone_mutation`, `handle_block_config_overwrite` |
| **Security / safety risk** | forging a gate-override token or authoring one's own approval; disabling a safety gate to get PAST it rather than to rescue a lockout; a history rewrite that conceals; a merge, review post, or reviewer assignment routed around the maker≠checker keystone. | `handle_block_out_of_band_merge`, `handle_block_raw_review_post`, `handle_block_self_reviewer_assign` |

Everything outside that table is allowed. The workflow gates below — plan-first, skill-loading, the orchestrator boundary, the `t3`-CLI bypass list, the blank-`general-purpose` dispatch refusal — do interrupt ordinary work, and that is legitimate only because each is **satisfiable or escapable by the agent in the same turn**: a per-call token plus a kill-switch, both indexed in § "Escape markers & kill-switches". A gate that interrupts development with neither is the defect this section names.

Relaxing a refusal in the table is the operator's call, not the agent's. Never author an override token asserting a consent nobody gave, and never disable a gate in order to get past it — the kill-switches exist to rescue a lockout, and `SELF_RESCUE_ALLOWLIST` is what keeps them reachable while a gate misfires.

## Conventions

- **One router, many events.** `scripts/hook_router.py` dispatches on `--event`. Registered events: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `TaskCreated`, `Stop`, `SubagentStop`, `PreCompact`, `SessionEnd`, `InstructionsLoaded`. Wiring lives in `hooks.json`. `SubagentStop` carries `session_id` / `cwd` / `transcript_path`, fires once per sub-agent termination, and carries three handlers: `handle_subagent_stop_no_commit` records a `terminated_without_commit` signal when the sub-agent's worktree (the harness `cwd`) is a work branch with 0 commits, so the orchestrator never reads a terminated agent as one whose work landed; `handle_subagent_stop_track_agent` records the terminating agent id in `<session>.agents-stopped`; `handle_subagent_stop_release` hands the agent's admission seat back to the interactive dispatch ceiling.
- **A session resume restores the whole background fleet in one step, and that restore has its own admission check.** The harness restores every previously-running background agent from its saved transcript at once. Whatever stagger the orchestrator applied belonged to the DISPATCH and is not replayed, and a restore is not a dispatch — so the dispatch-side gate cannot cover it, and an 8-core box can go from healthy to load 58 with 1 GB free without one intervening dispatch decision. `resume_admission_advisory` (the `hooks/scripts/resume_admission.py` sibling) runs inside `_merge_session_start_context`, so the directive rides the ONE `SessionStart` stdout write every path already goes through. The restored count is `<session>.agents` MINUS `<session>.agents-stopped`: the dispatch ledger is append-only and outlives its agents, so counting it alone warns on history. The ceiling is `teatree.core.admission_governor.resume_agent_ceiling` — `cores * HOST_AGENT_POPULATION_PER_CORE` scaled by the load headroom left under the same `BRAKE_LOAD_PER_CORE` watermark the dispatch lanes brake on, floored at 1. It is deliberately a LIVE machine reading, and deliberately NOT the per-lane `WRITE_CONCURRENCY_PER_CORE`, which bounds one lane and says nothing about the total agent population a box is carrying. Only `source == "resume"` is gated (a compaction is the same process and restores nothing). Fail-open throughout, and ordered so an idle resume is free: two small file reads first, and the `admission_governor_enabled` kill-switch (the only sqlite touch, read Django-free via `cold_reader`) only once the count is already over the ceiling.
- **Adding a gate** = a new handler registered on an existing event (usually `PreToolUse` or `Stop`). `hook_router.py` is a module-health-capped, **shrink-only** god-module: adding the handler body to it fails `check_module_health.py` (LOC and public-function ratchets only allow the file to shrink). So put a NEW handler in a **bare sibling module** (`hooks/scripts/<concern>.py`, like `django_bootstrap` / `unknown_repo_push_gate`) and import it into the router's `_HANDLERS` chain — the router puts its own dir on `sys.path`, so a bare `from <sibling> import <handler>` resolves both as the live hook and when imported as `hooks.scripts.hook_router` in tests. If the import + one-line registration still nudges the router over its cap, move a cohesive helper OUT in the same change so the file nets smaller — the extract-first rule, its mechanics (call-time back-imports, the one-line re-export, lowering `_CEILING_LOC`) and the `--report-debt` preview are in [`docs/module-health.md`](../docs/module-health.md). `handle_over_cap_growth_advisory` (the bare sibling `over_cap_growth_advisory.py`, registered on `PostToolUse`) says the same thing the moment a write grows an over-cap module, once per session per file; it rides `PostToolUse` because the post-edit body makes the net delta REAL rather than a guess, and because its `additionalContext` cannot collide with a second stdout payload on the same call — the only other `PostToolUse` writer, `handle_read_dedup`, fires exclusively on `Read`, which the advisory never handles (two payloads on one call would not parse; the exclusivity is pinned by a test). It can never deny (`PostToolUse` has no deny, the handler returns `None` on every path, and `tests/test_over_cap_growth_advisory.py` pins by source scan that no deny helper is reachable), so the enforcement stays with the commit ratchet. To **deny** a `PreToolUse` tool call, call the shared helper and return its `True`:

  ```python
  return emit_pretooluse_deny(reason)
  ```

  The helper writes the modern nested `hookSpecificOutput` schema alongside the legacy flat keys, and `main()` translates its `True` return into `sys.exit(2)`. **Never emit a deny payload at exit 0** — the harness silently ignores it and the tool call proceeds.

- **A gate only fires for tools wired into its event's matcher.** `mcp__*` tools are ordinary `PreToolUse` calls merely omitted from the matcher — adding the matcher string makes them fire, e.g. `mcp__glab__glab_mr_.*` routes a glab-MR-MCP create/update through the live `handle_validate_mr_metadata` validator (same metadata check as the `glab` CLI; fail-closed with the `T3_MR_VALIDATE_ALLOW_BROKEN_ENV=1` escape). The registered matchers are `Bash|Edit|Write`, `AskUserQuestion`, `mcp__.*[Ss]lack.*`, `mcp__glab__glab_mr_.*` and `Agent`, so the two `PreToolUse` `Agent` arms — `handle_dispatch_prompt_quote_scanner` and the `Agent` branch of `handle_enforce_orchestrator_boundary` — are LIVE. The orchestrator-boundary deny is default-ON (`[teatree] orchestrator_boundary_agent_gate_enabled`) and denies ONLY an EXPLICIT `run_in_background: False`: the Agent tool dispatches asynchronously and OMITS `run_in_background` from `tool_input`, so an absent field is read as a background dispatch and passes — reading absence as foreground false-blocks every main-agent Agent dispatch. Every off-ramp keeps it never-lockout: sub-agent context, an absent-or-`true` `run_in_background`, a per-call `[fg-ok: <reason>]` prompt token, the `= false` kill-switch, the deny-circuit-breaker, and — via `_fail_open_or_deny` — the self-rescue allowlist plus the master `danger_gate_fail_open` switch. Do NOT conflate the sub-agent dispatch tool with the task-LIST tools (`TaskCreate`/`TaskUpdate`/`TaskList`, below): those are what bypass `PreToolUse`, and `TaskCreated` is THEIR event, not a second dispatch seam — so the `Agent` matcher is the only interception point a dispatch has, for the dispatch-quote concern as well as the orchestrator-boundary one.

- **The MR-metadata gate watches every surface that sets a title/description, not just the inline create command.** `_extract_mr_fields` covers four: (1) inline `glab mr create/update --title/--description`; (2) the SAME command's file-based / heredoc description (`-F`/`--description-file`), read via `_read_message_file` rather than passed through as a falsely-empty (trivially "valid") string — but a double-quoted `$(…)`/`${…}`/`$VAR`/backtick value the hook cannot resolve before shell expansion is SKIPPED (`_looks_dynamic_value`) rather than validated as a truncated literal fragment, with the remote CI gate as the backstop; (3) out-of-band `glab api`/`gh api` PUT/POST to a `.../merge_requests` or `.../pulls` endpoint (`--field title=…`/`-f description=…`/`-f body=…`, the short flag either spaced or GLUED — `-Fdescription=…`/`-F'description=…'` sets the same field, and matching only the spaced spelling let a mixed command's back-fill report a PASS on a compliant title standing in for the description the forge would store) — the web-UI-equivalent edit that bypasses the create/update CLI, and the GitHub PR-create path (`gh api repos/<o>/<r>/pulls`). Under `--field`/`-F` (case-SENSITIVELY: `-f` is `--raw-field`, whose literal IS what the forge stores) a value opening with `@` names a FILE, so it is dereferenced and the FILE's text is validated — but only when the path is ABSOLUTE, names a REGULAR file (`stat` first: opening a FIFO never returns, and a read that outlives the router's budget kills every OTHER gate in the chain too) and is at most 1 MiB, GitLab's own description limit. Any other `@` value — relative, `@-`, `@`, non-regular, over-cap, unreadable — keeps the literal and is validated as text, and the refusal then NAMES that literal and the rule (`mr_deny_reason`) so the contract is not rediscovered by trial; (4) the `mcp__glab__glab_mr_*` MCP tools. The `gh pr create/edit` CLI is deliberately NOT a separate metadata surface: it is already governed by `handle_block_ai_signature` in the same chain, and double-gating would let the metadata deny preempt that gate's body scan. Both the out-of-band API path and the `glab mr update` CLI path (`extract_cli_mr_fields` in the sibling `mr_cli_fields`) validate ONLY the fields the command actually sets: a partial edit touching neither title nor description (`--field state_event=close`, `glab mr update --reviewer X`) is skipped, and a single-field edit back-fills the untouched one — by the canonical grammar a valid `type(scope): … (ticket_url)` line is simultaneously a valid title and a valid description first line, and an unset description on a title-only update is back-filled with a known-good `## What` body — so a partial edit can never false-block on `Title is empty.` or a missing What/Why. `glab mr create` keeps the stricter both-fields contract. **The CLI verb is detected against the command with quoted spans and heredoc bodies stripped (`strip_quoted_and_heredoc`)**, so the phrase merely embedded in a `git commit -m '… glab mr create …'` message, a doc string, or a heredoc body is text rather than an invocation; the residual is a real create/update fed *through* a stripped span (`bash -c "glab mr create …"`, a heredoc piped to a shell), a backstopped false negative. The `T3_MR_VALIDATE_ALLOW_BROKEN_ENV=1` escape and `T3_MR_VALIDATE_SCRIPT` override apply. **Every outcome that does NOT validate the MR names itself on stderr — the gate is never mute on the pass path.** A skip is typed (`gate_result.GateSkipped`, carrying its reason) rather than collapsed into the bare `None` that also means "not an MR mutation", and `handle_validate_mr_metadata` prints it via `gate_result.warn_gate_skipped`, the same posture as the crash and timeout warns. The three skip reasons: an unresolvable `$(…)`/`$VAR` title or description, a `glab mr update` setting neither field, and the `T3_MR_VALIDATE_ALLOW_BROKEN_ENV` opt-in. Exactly two outcomes stay silent: "not an MR mutation" and a clean PASS — a gate that recognises a call, declines to evaluate it and says nothing is indistinguishable from one that swallowed it, so whatever silence follows gets blamed on the gate.
- **The MR-metadata gate keys overlay resolution to the MR's TARGET repo, not the agent's cwd.** `mr_cli_fields.extract_mr_target_repo` parses the target slug from the same command — `-R`/`--repo <slug>` on `glab mr`, the URL-decoded namespace of a `glab api .../projects/<ns>/merge_requests…`, or the `owner/repo` after `repos/` in a `gh api repos/<o>/<r>/pulls…` — and `handle_validate_mr_metadata` forwards it as `t3 tool validate-mr --repo <slug>`. A dispatched agent inherits a cwd in whatever repo it was started from, so a cwd-keyed resolution grades an MR against a different overlay's rules and the any-overlay-pass fallback lets it through. When the target maps to exactly one registered overlay, `validate-mr` validates ONLY against that overlay with NO any-overlay-pass fallback, and a crash in that overlay's validator FAILS CLOSED (deny) rather than skipping. A blank or unmatched `--repo` falls back to cwd-keyed resolution, so an MR targeting the cwd repo is unaffected.
- **A `glab mr create` glab would silently no-op is refused, not allowed into the void.** `handle_block_glab_stale_base_remote` (the bare sibling `hooks/scripts/glab_stale_base_remote_guard.py`, registered right after `handle_validate_mr_metadata`). `glab` reserves the remote name `glab-base` and PERSISTS a `-R <slug>` override into the cwd repo as a remote of that name; the next `glab mr create -R <different-slug>` from that directory hits the stale override and glab bails — **exit 0, no output, no MR**. Reads (`glab mr list`) are unaffected, so the repo looks healthy, and a must-fail call and a should-succeed call become the same empty result, which reads as a swallowed hook. The gate fires narrowly — a real `glab mr create` (verb detected on the quote/heredoc-stripped skeleton) with an explicit `-R`/`--repo` target, run in a directory (a leading `cd <dir> &&` wins over the harness `cwd`) whose `glab-base` remote points at a different project — and names the remote, the target and the two fixes (run from the target repo's own clone, or rename the remote). A matching `glab-base`, an absent one, no `-R`, a non-git cwd, or any other command all ALLOW. Never-lockout: a per-call `[glab-base-ok: <reason>]` token and the `[teatree] glab_stale_base_remote_gate_enabled = false` kill-switch (`t3 <overlay> gate glab-base-remote disable`) both ALLOW, the deny routes through `_fail_open_or_deny`, and every internal error fails OPEN.
- **NEVER directly assign a reviewer — `handle_block_self_reviewer_assign` blocks every reviewer-assignment surface.** Reviewers are never set directly on an MR/PR, least of all the owner's OWN MR. Colleague review is REQUESTED via the Slack/approval channel (`review-request post`); the only assignment that exists is the overlay's standing `pr_auto_reviewers` policy. The gate (the bare sibling `hooks/scripts/no_self_reviewer_assign.py`, registered right after `handle_validate_mr_metadata`) covers the CLI `glab mr create/update <iid> --reviewer/--reviewers <user>`, `gh pr create --reviewer/-r`, `gh pr edit --add-reviewer/--reviewer`, an out-of-band `glab api`/`gh api`/**`curl`** WRITE setting `reviewer_ids`/`reviewers`/`requested_reviewers` on a `merge_requests`/`pulls` endpoint (a GET *read* of the same field is allowed — the block is gated on the effective HTTP method, and each client's own body flags are consulted because `-f` is a gh field while curl's `--fail` is not), and the `mcp__glab__glab_mr_update`/`mcp__glab__glab_mr_create` MCP tools carrying a reviewer arg. It is SEPARATE from the MR-metadata gate, which deliberately SKIPS a `--reviewer` update because it validates only title/description. The verb is detected on the quote/heredoc-stripped skeleton (`mr_cli_fields.strip_quoted_and_heredoc`) so the phrase inside a commit message or doc string does not false-fire. The one sanctioned way a reviewer is ever set is the overlay's `pr_auto_reviewers` config: applied in-process by `create_pr` in the same POST that opens the MR, and — for MRs already open when the policy landed — by `t3 <overlay> review apply-reviewer-policy`, which takes no username and touches only the factory bot's own MRs. BOTH halves are scoped by `OverlayConfig.acts_as_distinct_identity_on`, so the policy reaches only a repo the overlay writes under a non-owner credential; on every other repo the owner is the AUTHOR, and assigning him there would be the self-assignment this gate refuses. Neither needs an exemption: the first is in-process, and the second is neither a forge CLI nor a REST leader, so the matcher never sees it. Never-lockout: a per-call `[reviewer-ok: <reason>]` token (a vetted one-off on a colleague's MR) and the `[teatree] no_self_reviewer_assign_gate_enabled = false` kill-switch both ALLOW; the deny routes through `_fail_open_or_deny`.

- **`TaskCreated` can NEVER block — a deny there DELETES the user's todo item.** The event has exactly ONE producer, the `TaskCreate` tool's own `call()`. No fan-out dispatch reaches it, so a "task" here is a TODO ITEM: it spawns nothing, has no dispatch prompt, and `teammate_name`/`team_name` carry the CURRENT session's identity rather than a dispatch target. `call()` writes the task row FIRST, then runs the hooks, then on any blocking result awaits a DELETE of that row before raising — so a gate that denies here destroys data instead of preventing anything.

  The reason is discarded too: the output mapper sets `preventContinuation`/`stopReason` from `{"continue": false, …}` and sets `blockingError` ONLY from `{"decision": "block", "reason": …}`, while `TaskCreate` reads ONLY `blockingError`. The block that actually fires is the exit-2 fallback, whose message is literally `No stderr output` because teatree keeps stderr clean on deny. So the router refuses to exit non-zero on this event at all — `_NEVER_BLOCKING_EVENTS` in `hook_router.py`, pinned by `tests/test_hook_router_task_created_never_blocks.py` — and a handler's `True` return is inert. **To make a `TaskCreated` gate visible, write `{"systemMessage": <text>}` at exit 0.** `{"decision": "block", "reason": …}` is NOT an alternative: it surfaces the reason but STILL deletes the task.

  Because the event governs a task-list entry, a demand keyed on dispatch-ness is unsatisfiable by construction here: nothing reads a todo as a prompt, so demanding the entry name its skills silently kills task tracking, and charging an admission seat books one for an agent a todo never puts on the box. ONE handler rides the event — `handle_dispatch_prompt_quote_scanner_on_task_create`, which scans the entry's OWN text for a HIGH verbatim user quote, a property of the TEXT rather than of a dispatch. It ships on (`[teatree] dispatch_quote_gate_on_task_create_enabled = false` turns it off), clears on a `[quote-ok: <reason>]` token, and fails open on a missing `session_id`. NOTE: the harness aborts the event on ANY handler stderr, so `main()`'s traceback-printing swallow is a lockout here rather than a backstop — a handler on this event must catch its own exceptions and fail OPEN in-handler.

- **Skill-loading `PreToolUse` gate narrows to task-intent and has a per-call escape.** `handle_enforce_skill_loading` (matcher `Bash|Edit|Write`) hard-blocks until every *resolvable* unloaded skill in `<session>.pending` loads. The demand set derives from genuine task-intent text only: `skill_loader_input.build_skill_loader_input` runs the prompt through `strip_ambient_context` first (both in `hooks/scripts/skill_loader_input.py`, shared with the SessionStart injection), removing the harness-injected `<system-reminder>` / `<command-*>` wrappers — the CLAUDE.md body, the MEMORY.md index, the skills listing — so an ambient index line carrying a topic keyword cannot keyword-match the supplementary skill map and hard-block an unrelated autonomous loop. The gate honours a per-call `[skill-load-ok: <reason>]` token in the current tool call's command/args (`command` for Bash, `new_string`/`content`/`file_path` for Edit/Write, first 512 chars; empty reason rejects), so a false trigger can never wedge the loop while a genuine intent match still blocks every call lacking the token. `strip_ambient_context` runs on every `UserPromptSubmit`, so its input is length-capped to `_AMBIENT_STRIP_MAX_CHARS` (64 KiB) before the DOTALL regexes run — a large pasted log quoting literal `<system-reminder>` open tags must not blow the 30s timeout.
- **A gate that keys on the `Edit`/`Write` TOOL NAMES is blind to a file written through Bash — both write-gates consume one shared resolver.** `teatree.hooks.write_targets.bash_write_targets(command)` answers "which paths would this command write?" from the quote-accurate shell lexer: `>`/`>>` redirect targets (including the `> path <<EOF` form), `sed -i`, `tee`, `cp`/`mv`/`install` destinations, `git mv`, and an interpreter body (`python3 - <<PY`, `python3 -c`, `bash <<SH`) — a shell body is classified recursively, a Python body yields its literal `open(p, "w")` / `Path(p).write_text(...)` targets. It is PRECISION-biased: a target it cannot pin statically (a `$VAR` path, a glob, a Python body writing through a variable, or a `>(...)` process substitution, whose split-token remainder is not a path) is reported as `unresolved` rather than guessed at, because a false positive blocks legitimate shell work while a false negative only loses coverage the tool-name arms never had. Each consumer applies its OWN posture — the main-clone guard ALLOWS an unresolvable target, matching its stance on an unpinnable git target; the plan gate WARNS. Relative targets are anchored to the command's effective dir via `main_clone_guard._effective_command_dir`, so a leading `cd` / `git -C` is honoured and the ambient `cwd` never mis-anchors the decision.
- **Plan-before-code write-block gate has three never-lockout escapes.** `handle_block_edit_before_planned` (`PreToolUse`, matcher `Bash|Edit|Write`; the handler lives in the bare sibling `plan_edit_gate.py` because the router is shrink-only) denies file writes when the cwd's worktree ticket is still in `STARTED` FSM state — an `Edit`/`Write`, or a `Bash` command whose write targets land inside the cwd's repo. The Bash classification runs BEFORE the ticket-state lookup, so an ordinary read-only `Bash` call never pays for a Django bootstrap; a write whose target cannot be pinned emits a one-line stderr NOTE and ALLOWS. Three escapes: (1) **per-call token** — `[skip-plan-gate: <reason>]` in the Edit `new_string`/Write `content`/either `file_path`/the Bash `command` (first 512 chars; empty reason rejects) ALLOWs that single call; (2) **config kill-switch** — `t3 <overlay> config_setting set plan_edit_gate_enabled false` (default on, fails OPEN to enabled on missing/broken config); (3) **self-rescue CLI** — `t3 <overlay> gate plan disable`. The ticket state is resolved via `_ticket_state_for_cwd` → git toplevel → `Worktree.extra['worktree_path']` → `Ticket.state`; a non-STARTED state, a missing ticket, or any resolver error all fail OPEN. The deny routes through `_fail_open_or_deny` and stamps a small non-privacy `gate_id = "plan_gate"` marker on its output so the transcript-conformance eval (`no_code_edit_before_planned`) can key on THIS gate's deny without reading the raw deny reason; the token scanner lives in `plan_edit_gate.skip_plan_gate_token`. This token is the per-edit escape for *this hook*; the FSM-level plan gate (`check_plan_artifact`, the `plan()` transition) has its own escapes — `t3 <overlay> ticket skip-planning <id> --reason "<why>"` records an audited `trivial_plan_skip` marker that advances STARTED → PLANNED with no `PlanArtifact`, and `ticket plan-bypass --human-authorize` covers the no-real-plan-but-needs-sign-off case. Once PLANNED, edits are no longer blocked by this hook.
- **Standing verified-green stop-gate.** `handle_standing_goal_stop` (the bare sibling `standing_goal_stop_gate.py`, registered in the `Stop` chain right after `handle_completion_claim_gate`) DENIES a stop-as-if-done while a registered `StandingGoal` (`t3 goal set <name> --check "<cmd>"`) is unmet: it re-runs each active goal's `check_command` at turn-end (short timeout, briefly cached), and on a non-zero exit emits `{"decision": "block", ...}` leading with the blunt binary (`` `<goal>` green? NO.``) and minting a single-use escape token. A passing check auto-retires the goal (`active` → False). Precision mirrors the completion-claim gate: it fires ONLY on a loop-driven turn (`_session_drives_loop`), short-circuits the `stop_hook_active` re-fire, and honours the kill-switch. Never-lockout, critical for a stop-gate: (1) attended turns are skipped; (2) the single-use token — end the turn with `[standing-goal-hold: <token> <reason>]` to hold this ONE stop; the token dies after one use, so it is never a blanket bypass and the deny re-fires on the next stop while unmet; (3) kill-switch `[teatree] standing_goal_stop_gate_enabled = false` (`t3 <overlay> gate standing-goal disable`); (4) crash-proof — ANY internal error, an unbootstrappable Django, an unreadable goal, or a check that times out or errors all ALLOW the stop. Only a check that ran and exited NON-ZERO denies. Detail: handler docstring + the `StandingGoal` model.
- **Standing directives are DELIVERED by this plugin, but OWNED by teatree, and the GATE FOLLOWS THE COST.** `emit_standing_directives_once` (the bare sibling `loop_registrations.py`, called from `handle_enforce_loop_on_prompt`) maps each resolved directive's declared `wakes_session` onto one of two delivery shapes. A slot that does NOT wake the session is written into the turn that is already happening, as plain context: it costs no turn, so it arms nothing and keeps the WIDE `_teatree_engaged` gate — every engaged session, from its first prompt, re-delivered no more often than the slot's own interval (deliberately NOT emit-once; repeated delivery is the mechanism). A slot that DOES wake the session becomes a recurring `/loop <duration> [<slot_id>] <text>` registration, which IS arming the loop machinery, so it gates on `_loop_auto_load_active` — `.t3-engaged` engages only the suggester while the loop machinery consults `.teatree-active`, and a session engaged by a lifecycle skill alone must therefore arm NOTHING. A `scope` of `attended-singleton` additionally requires `_session_owns_loop` (claimed here idempotently), so a host-global slot is driven once per host rather than once per session. Each shape keeps its OWN per-session marker (`<session>.directives-injected` carrying the last delivery instant per slot, `<session>.directives-registered` carrying the slots already registered), because the singleton slot's eligibility is decided later in the same handler than the others' and a shared marker would strand it. **Neither marker is reaped from this module.** N engaged sessions is the normal operating mode and no session can distinguish a dead peer's marker from a running one's, so a per-prompt foreign-marker sweep deletes the very state its peers throttle on — every prompt then re-injects the zero-turn text and re-registers the self-waking slots, and the `/loop` population grows with prompt count. That is the runaway `self_woken_turns_per_hour` exists to bound, and its pinned `{per_session: 2, per_host_singleton: 6}` holds only at N=1. Both suffixes are left to the router's own throttled age sweep (`_sweep_stale_state_files`, 2-day retention), which reaps on mtime and therefore reaps only what has stopped being written; `directives-registered` is rewritten unchanged on each of its own session's prompts, since it is otherwise written once and would age out underneath the session holding it. The split is the point: text, cadences, scope and delivery cost are harness-neutral teatree data (`t3 loop directives show --json` is the contract), and THIS module is an adapter carrying no directive text, no cadence value and no policy — pinned by a layer-purity test whose denylist is DERIVED from the layer-1 texts, plus an exact-line round trip at the length cap. The Agent-SDK lane is excluded from both shapes (a factory worker is FSM-governed and has no user-request channel). **Both gates are read before the resolver, never after.** `_standing_directives` bootstraps Django (measured 1.67s cold) and this runs on every prompt, so `_nothing_deliverable` decides from the markers and the two seams alone — `_loop_auto_load_active` implies `_teatree_engaged`, so an unengaged session exits on the first check, and an engaged session that arms no loop exits on the earliest next-due epoch `directives-injected` carries alongside its per-slot instants. Advisory and crash-proof: it never denies, and any failure — an unbootstrappable Django, an unreadable marker, a raising resolver or ownership probe — emits nothing rather than raising into the 30s `UserPromptSubmit` budget.

Scoped to the `autoload` tier deliberately — a session engaged by loading a lifecycle skill (`.t3-engaged`) made no standing request, so forcing the platform skill on it would be an over-block. - **A plugin-owned skill in `<session>.pending` is enforceable under its OWN namespace.** The write boundary canonicalizes a plugin-owned bare name UP to `<namespace>:<name>`, so `_skill_resolves` must de-qualify before looking for a directory: no directory is named verbatim `<namespace>:<name>`, and a literal lookup warns every plugin-owned demand to stderr as unresolvable, leaving the gate open. `_dequalify_own_namespace` applies the exact inverse of `_canonical_skill_token`'s promotion arm for THIS plugin's namespace only. - **The banned-terms carve-out prefers the offline allowlist over the live probe.** `publish_surface.carve_out_applies` resolves a target repo's visibility from the `[teatree] private_repos` substring allowlist FIRST — the reliable, network-free, in-hook mechanism and the recommended way to declare private overlay repos. The allowlist match (`_repo_visibility.slug_is_allowlisted_private`) is HOST-QUALIFICATION-SYMMETRIC: an entry may be written bare (`owner/repo`) or host-qualified (`host/owner/repo`, the form a repo URL and `slug_for_cwd` carry), and either form matches both the commit surface (host-qualified cwd slug) and the pr-create surface (the BARE `owner/repo` slug `gh pr create --repo` supplies) — without the symmetry one repo is classified two ways across surfaces. The live `gh`/`glab` visibility probe is a best-effort fallback only: the PreToolUse subprocess inherits a restricted PATH/env, so the probe resolves the tool against an augmented PATH (`_PROBE_PATH_EXTRA`) but still fails to "unknown" when the tool is absent or auth differs. Unknown ALWAYS fails closed (the target is treated as NOT private, the deny stands), and the gate emits a one-line stderr `NOTE` naming the unknown slug and pointing at `private_repos`, so the over-block is diagnosable instead of silent.

  The posting-path carve-out is an ALLOWLIST (`command_is_pure_private_gh_glab_post`), not a denylist: it DOWNGRADES only when it can PROVE every top-level segment is a benign `cd`/env nav segment or a structurally-pure `gh`/`glab` post (`words[0]` EXACTLY `gh`/`glab` after a benign prefix; every token a flag, an opaque flag-value, or a positional with no execution-transport or substitution construct) targeting a known-private repo, with at least one posting segment — and FAILS CLOSED on everything else. Do not invert this into detect-hidden-bad: enumerating shell `-c` / `env -S` / here-string / `eval` / pipe-to-shell leaks on every un-enumerated transport, whereas under the proof a hidden public post requires a second non-`gh` verb, a transport construct, or a public `--repo`. Symmetrically on the DETECTION side, `is_publish_command` is opaque-transport-aware — a wrapper / path-form / env-prefix forge post (`sh -c "gh …"`, `eval`, `xargs gh`, `env GH_PAGER= gh`, `/usr/bin/gh`, `foo=1 gh …`) is detected as a publish (its leader canonicalized by basename and wrapper-stripped, mirroring `raw_merge_detect`) so it is SCANNED and fails CLOSED at BOTH the banned-terms and quote gates, and an unresolved `gh`/`glab` WRITE destination is scanned unless provably non-public.

  A construct in the command does not disqualify a PROVABLY-private post: `public_visibility._construct_bearing_segment_verdict` keeps a `-d "$(cat body.md)"` / heredoc-writer / `$VAR` body toward a LITERAL allowlisted, namespace-matched or probe-confirmed-private destination skip-eligible — a private target has no public-leak surface, so a scan-impossibility sentinel never blocks it and no `ALLOW_BANNED_TERM=1` / `QUOTE_OK=1` escape is needed. A live substitution that DETECTABLY publishes (`$(gh … create …)`), a `$`-carrying slug, or a PUBLIC/UNKNOWN target still forces the fail-closed scan.

  A `git commit` is LOCAL and cannot leak before a push, and the pre-push gate (`refuse-public-push-with-leak.sh` → `scripts/privacy_scan.py`) re-scans every commit MESSAGE via `git log --format='%B'` as well as the diff. So a local commit DOWNGRADES to a warn regardless of the landing repo's visibility (PUBLIC included), via `command_targets_local_commit` — a READABLE body (`-m`, `-F <file>`, `-F -` stdin, heredoc, `printf|git commit -F -`) is resolved and scanned so the matched term is NAMED in the warn, and a genuinely-unreadable body downgrades the same way. A `git commit -F <relpath>` body file unreadable from the cold hook's reset cwd is retried against the dir whose repo the commit LANDS in (`_body_file_resolution.commit_body_file_base` → the command's own `cd`/`-C`/`--git-dir`, else the harness `cwd`), so the gate scans the real body instead of fail-closing on an unread one; the same extractor backs the bare-reference gate. The chained-segment proof (`command_targets_local_commit`'s `_chained_segments_provably_inert`) keeps a commit chained to a real PUBLIC `gh`/`glab` post hard-blocked, and a `gh`/`glab` POST with no push gate behind it still hard-blocks a PUBLIC body: a banned term reaches the public world only via a forge POST or a `git push`, both of which hard-block, so the commit-time downgrade is pure defense-in-depth.

  Two term-level downgrades. `term_is_own_repo_slug` matches by token-CONTAINMENT, not whole-slug equality: the org PREFIX token of a multi-token private slug (`acmecorp` of `acmecorp-engineering`) qualifies, since a work-item URL `host/acmecorp-engineering/.../-/issues/N` tokenizes the prefix out of the repo's OWN identity, while a SUPERSET term (`acmecorp-engineering-services`) is longer than the entry's token run and stays blocked; its `own_slug_term_downgrades` arm runs `commit_branch_downgrades` and fires FIRST with its specific message for a provably-private landing. Separately, for a post to a PUBLIC surface whose body cites the address of a configured private repo, `own_repo_url_carve_out.term_only_inside_own_repo_urls` blanks every forge URL whose host+namespace matches a `private_repos` entry (host-qualification-symmetric) and downgrades to a warning ONLY when the term then has NO remaining occurrence — the structurally-required URL of an own work item is not a leak, while a bare term outside such a URL, or a term in a foreign URL, still hard-blocks. It fires only for the structured `gh`/`glab` posting verbs (`is_gh_glab_posting_command`), never for `git commit`, which keeps its own landing-repo carve-out above.
- **A term list has no token for "this is someone's private message" — the verbatim operator-paste gate.** The banned-terms gate answers *"does this text contain a forbidden token?"* and the quote-scanner answers *"does this text have the SHAPE of a quotation?"*. - **The headless-posture authoring gate keys on WHO IS ACTING, and is the one gate that fails OPEN.** `handle_block_interactive_authoring` (the bare sibling `hooks/scripts/headless_authoring_gate.py`, registered right after `handle_block_main_clone_mutation`) refuses an INTERACTIVE Claude Code session that authors teatree — an `Edit`/`Write`/`NotebookEdit` under the repo's authored dirs, an `Agent` dispatch of an implementation sub-agent (`t3:coder`/`t3:debugger`/`t3:tester`/`t3:e2e`/`t3:shipper`/`t3:planner`), or a `git commit`/`push` in a teatree repo. Reading, searching, reviewing, merging, answering questions, filing issues, and every `t3` command (including the host-mutating dogfooding ones — `reclaim-disk`, `clean-all`) stay ALLOWED: the main session monitors and dogfoods, the factory implements. **The factory's own workers run through the Agent SDK with this same hook set**, so the gate discriminates by LANE, not by path: `session_lane()` reads the SDK transport's env contract (`CLAUDE_CODE_ENTRYPOINT=sdk-py`, `CLAUDE_AGENT_SDK_VERSION` set, `CLAUDECODE` stripped from the child env) and refuses ONLY a positively-identified interactive CLI session. **It fails OPEN, inverting the house rule** — an unreadable lane signal, an unreadable posture, or any internal error ALLOWS, because a wrong refusal halts the whole factory and every SDK consumer while a wrong allow costs one hand-written edit a human notices. Two carve-outs: work already in flight (a path inside a LINKED worktree — a `.git` *file* — is a checkout that already exists for this ticket, so only NEW work authored in a primary clone is refused), and the audited single-use `[headless-authoring-ok: <reason>]` token, which unblocks exactly one call and appends a line to `<session>.authoring-overrides`. **The in-flight carve-out applies to `Bash` as well as to the file tools**: a `Bash` call names no file, so `_is_authoring_call` asks BOTH repo questions of one probe (`_bash_repo_probe`) — otherwise an edit inside a live worktree is allowed while the `git commit` finishing that same edit is refused, and the refusal text advertises an exemption the `Bash` branch does not implement. **That probe is built from the dir the write LANDS in, not from the ambient `cwd`**: `_commit_repo_dir.resolve_commit_dir` (the same resolver `main_clone_guard`, `single_branch_repo_guard` and the banned-terms commit carve-out use) honours a leading `cd <dir> &&`, a `git -C <dir>` and a `--git-dir`, so only the repo actually being written to is gated — keying on the raw `cwd` makes the gate a SESSION-wide ban, refusing every commit and push to any repository at all. An unresolvable target (`$VAR`, a `cd` onto no real dir) yields an empty probe, which ALLOWS, matching this gate's fail-OPEN posture. The `git commit`/`push` verb is detected on the quote/heredoc-stripped skeleton (`mr_cli_fields.strip_quoted_and_heredoc`, as in every sibling gate), so a read-only `python - <<'PY'` probe or a `--grep` pattern that merely CONTAINS `&& git push` is not refused; a `git commit`/`push` whose resolved target is a primary clone of a managed repo still is. Kill-switch `[teatree] headless_authoring_gate_enabled = false`; the deny routes through `_fail_open_or_deny`, so the self-rescue allowlist and the master `danger_gate_fail_open` switch apply too. The matcher is `Bash|Edit|Write|NotebookEdit`.
- **The main-clone guard has three arms, not two.** `handle_block_main_clone_mutation` (`hooks/scripts/main_clone_guard.py`) denies a working-tree mutation of a REGISTERED teatree main clone: an `Edit`/`Write` to a path under a clone on the default branch, a forbidden git command (`checkout`/`switch` off-default, `reset --hard`, `restore`, `stash pop`) keyed off the command's EFFECTIVE dir, and a `Bash` command whose WRITE TARGETS resolve under such a clone (`sed -i`, `cat > path <<EOF`, `tee`, `cp`/`mv`, a `python3` heredoc). The two tool-name arms leave a hole exactly the width of the shell: a session's cwd drifts into the deployed clone, files there are rewritten by shell commands, nothing fires at write time, and the guard only speaks up on the git command used to REVERT — by which point the shared base is already dirty. An UNRESOLVABLE write target ALLOWS, matching this module's posture on an unpinnable git target, and a clone sitting on a non-default FEATURE branch keeps its carve-out on the Bash arm too. Never-lockout: the per-call `[main-clone-ok: <reason>]` token (scanned in `command` as well as the Edit/Write fields), the `[teatree] main_clone_guard_gate_enabled = false` kill-switch (`t3 <overlay> gate main-clone disable`), and `_fail_open_or_deny`.
- **The whole-tree `git add` gate refuses the sweep before anything is staged.** `handle_block_git_add_all` (the bare sibling `hooks/scripts/git_add_all_guard.py`, registered right after `handle_block_direct_commands`) denies `git add -A` / `git add --all` / `git add .` in a `Bash` command. The sweep commits what nobody meant to commit — a scratch file written beside the code being edited, and, in a worktree shared with another agent, that agent's in-progress edits under the wrong authorship — and the only other backstop (`tests/test_repo_root_minimal.py`) runs AFTER the commit exists and sees only the repo root. Deliberately narrow: `git add <explicit paths>` always passes, and so do `git add -p` and `git add -u` (tracked files only — no untracked sweep), including with a `.` pathspec. A no-sweep flag WINS over a sweep flag it is combined with — `git add -An` / `git add --all --dry-run` stages nothing, `-A -p`/`-A -i` stage hunk by hunk under the author's eye, and git itself dies on `-A -u`. The verb is detected on the quote/heredoc-stripped skeleton (`mr_cli_fields.strip_quoted_and_heredoc`), so the phrase inside a commit message, a PR body or a heredoc is text rather than an invocation. The deny names the explicit-path form and the session scratch directory. Never-lockout: the per-call `[add-all-ok: <reason>]` token (the genuine "yes, the whole tree" case — a first commit on a scaffolded directory), the `[teatree] git_add_all_gate_enabled = false` kill-switch (`t3 <overlay> gate add-all disable`), and `_fail_open_or_deny`. A narrow targeted-command gate: it refuses exactly one command shape, never arbitrary Bash.
- **A blank `general-purpose` sub-agent is REFUSED for managed-repo work.** `handle_block_general_purpose_agent` (the bare sibling `hooks/scripts/general_purpose_agent_gate.py`, registered right after `handle_enforce_skill_loading`) denies an `Agent`/`Task` dispatch whose `subagent_type` is `general-purpose` — or absent, which defaults to it — when the brief names a repo the overlay registry declares managed. Such an agent starts with ZERO context (no skills, no repo guidelines, no runbook, no memory), so it rediscovers the stack from scratch and works outside the workflow. The refusal names the agents that carry the context — `t3:coder` / `t3:debugger` / `t3:tester` / `t3:e2e` / `t3:reviewer` / `t3:bughunter` / `t3:planner` / `t3:shipper`, or `Explore` for read-only fan-out — so the caller can re-dispatch immediately. WHICH repos count is overlay knowledge, read from `managed_repo.overlays_registry`'s `workspace_repos` / `frontend_repos` / `public_repos` slugs (each slug and its path segments, word-boundary anchored so `acme-product` matches inside `wt-acme-product-42` but never inside a longer word) — so this module names no repo itself, and an overlay declaring none disables the gate for itself. Scoped to the `Agent`/`Task` tool names by EXACT match: the `TaskCreate`/`TaskUpdate` todo writes carry a description and no `subagent_type`, so a prefix match would deny them and block task tracking. Never-lockout: the per-call `[general-purpose-ok: <reason>]` token (an empty reason does not unblock, and only the first 512 chars of each field are scanned so a buried marker cannot silently authorise the call), the `[teatree] general_purpose_agent_gate_enabled = false` kill-switch (`t3 <overlay> gate general-purpose disable`), an unreadable registry (no tokens → no deny), and `_fail_open_or_deny`.
- **A hand-rolled "has this branch landed?" probe earns one advisory, never a deny.** `handle_warn_merged_detection_probe` (the bare sibling `hooks/scripts/merged_detection_probe_gate.py`, registered LAST-but-two in the `PreToolUse` chain beside the other WARN-only nudge) writes one stderr line when a `Bash` command runs `git cherry` / `git branch --merged` / `git merge-base --is-ancestor <sha> <default>` / `git log … --not` / `git log <default>..<sha>` against a DEFAULT-branch-shaped target (`origin/main|main|origin/master|master`), and points at `t3 <overlay> workspace branch-verdict <branch>` plus the per-change content read (`git show origin/main:<path> | grep`, `git log -1 -S`) — the read-only serialization of the three-layer content classifier (#4070). A squash-merge rewrites the branch's shas, so every per-commit / ancestor primitive reads landed work as unmerged; an orchestrator that hand-rolled `git cherry origin/main HEAD` across ~18 worktrees escalated three already-merged branches to the owner as false completions. It is WARN-only by design: the same command a coder runs mid-rebase, so intent cannot be split reliably, and a deny would sit on the git hot path. The TARGET SHAPE is what separates the two — `repro.py`'s two-sha `merge-base --is-ancestor` provenance proof and a `git cherry upstream/topic HEAD` rebase read name no default branch and stay silent, as do a two/three-dot `git log`/`git diff` range and the phrase inside a quoted string. The canonical detector needs no carve-out: `branch_classification` shells out through Python `subprocess` in the worker, and a PreToolUse hook sees only the agent's own Bash calls. Never-lockout: the per-call `[merge-detect-ok: <reason>]` token, the `[teatree] merged_detection_gate_enabled = false` kill-switch (`t3 <overlay> gate merged-detect disable`), and a silent fail-open on any resolver error. The shape detection lives in the `teatree.hooks.merged_detection_probe` leaf (lazily imported inside the `managed_repo.teatree_src_on_path` `src/` bootstrap); the `src/` half of the same boundary is held hard by `tests/conformance/test_merged_detection_single_home.py`.
- **An UNBOUNDED orchestrator read is REFUSED — delegate it or bound it.** `handle_block_undelegated_investigation` (the bare sibling `hooks/scripts/orchestrator_delegation_gate.py`, registered between `handle_enforce_orchestrator_boundary` and `handle_enforce_orchestrator_investigation_boundary`) denies a main-agent `Bash`, `Grep` or `Glob` call whose SHAPE has no ceiling on what it returns. The boundary it enforces is otherwise uncovered: the heavy-Bash gate keys on DURATION and a sweep is fast, and the investigation nudge is WARN-only and structurally forbidden from denying — so an inline `rg` sweep, a log trawl or a `… --json | python3 -c` reduction meets nothing that refuses. THE LINE is *routing reads a fact; investigation builds understanding*, decided from the command alone because a `PreToolUse` hook cannot see an output that does not exist yet. Two shapes qualify: a SWEEP (`rg`, `grep -r`, `git grep`, `find <path>`) carrying none of the three bounds — a count bound (`-m`/`--max-count`), a `| head`/`| tail`, or a NAMED single file, since a search over one file is bounded by that file and gating the `rg` spelling while the `grep` one passes gates the spelling rather than the shape (a glob is not a name: it is how a tree walk is spelled) — and a PARSE (output piped into `python`/`node`/`ruby`/`perl`), which is the shape of *this was too big to read, so I wrote a program to reduce it*. The sweep patterns are anchored to a command HEAD and deliberately never fire after a single `|`, so a `grep` used as a downstream FILTER over an already-bounded output (`docker ps | grep teatree`) still passes — as do `git status`, `docker ps`, `gh pr view`, `t3 … list --json`, `| jq '.field'`, `head -50` and `sed -n '1,80p'`. `jq`/`awk`/`sed` and a BARE `python3 -c` are deliberately absent: they are field extractors and routing arithmetic. This is NOT an arm of the heavy-Bash gate because the two guard different resources and so cannot share an escape — that gate guards RESPONSIVENESS, which backgrounding discharges, while this guards CONTEXT, which a backgrounded sweep still spends the moment its output is collected, so `run_in_background: true` is NOT an escape here. Nothing the heavy denylist already covers is re-listed. The refusal TEACHES both levers — the agent to dispatch (`Explore` for a code sweep, `t3:debugger`, `t3:bughunter`, `t3:reviewer`) and how to bound the call if it really is one routing fact. The NATIVE spelling of the same sweep is gated too, or the gate is routed around by construction — an orchestrator refused `Bash(rg …)` switches to `Grep(…)` and never meets it again. Each native tool gets the Bash arm's own bounds mapped onto its parameters: a `Grep` is bounded by `head_limit` or by a `path` naming ONE file, a `Glob` only by its pattern, whose basename must carry a literal stem (`**/*_scanner.py` passes; `**/*.py` is the `find . -name '*.py'` walk the Bash arm already refuses). `Glob` deliberately UNDER-blocks a broad-stem pattern: it returns paths rather than content, so a wrong refusal costs more than a missed one. `Read` is not gated — one named file is the bounded shape `head -50` already passes under. Every other tool is allowed BY CONSTRUCTION rather than by an allowlist that goes stale, so `Agent`/`Task`, `TaskCreate`/`TaskUpdate`, `SendMessage`, `AskUserQuestion` and every session-bound MCP connector (Slack/Notion/SharePoint/Drive) always pass. Scope is the ORCHESTRATOR only, via the discriminators the sibling gates already share — `call_is_from_subagent` (a sub-agent sweeping is doing its job), `session_lane() == interactive_cli` (the factory's own SDK workers are untouched) and `_teatree_engaged`. Never-lockout: the per-call `[delegate-ok: <reason>]` token (empty reason does not unblock), the `[teatree] orchestrator_delegation_gate_enabled = false` kill-switch (`t3 <overlay> gate delegation disable`), `_fail_open_or_deny`, and fail-OPEN on any internal error — an unreadable lane or posture is not evidence of investigation. A native call carries no free-text field the `[delegate-ok:]` token can practically ride in, so its per-call escape is the BOUND itself — which satisfies the gate rather than bypassing it.
- **The admission governor is consulted on the interactive dispatch.** `handle_dispatch_admission` (`PreToolUse`, `Agent`/`Task` — the ONE interception point a dispatch has) lives in the bare sibling `hooks/scripts/dispatch_admission_gate.py` and denies a dispatch the governor refuses, quoting its own `reason` so the refusal names which brake fired. The verdict lives in `teatree.core.dispatch_admission` — all three lanes route through the one pure decision function, so they can never diverge; without this arm an orchestrator dispatch is admitted with no ceiling and no load brake while the agent population on the box is the SUM of both lanes. The ceiling is compared against the TOTAL live-agent count — durable `Task` claims (both execution targets) plus live `InteractiveDispatch` seats, deduped per session with `max` so a claim and the seat it produced are one agent rather than two, with only a session's FIRST dispatch credited for its own still-unseated claim. A sub-agent's onward dispatch (`agent_id` present) skips the CEILING because its own lane already admitted it and its own claim is counted there; the brakes apply in every case. Kill-switch is the EXISTING `admission_governor_enabled` (deliberately no second flag, which would let the two drift); per-call escape `[admission-ok: <reason>]`; the deny routes through `_fail_open_or_deny`; and an unbootstrappable Django, an unimportable `teatree` or ANY internal error all fail OPEN. **An admitted dispatch takes a durable SEAT.** `Task.objects.active_claims()` cannot see an ad-hoc `Agent` dispatch — it creates no `Task` row — so without a seat the ceiling is blind to its own admissions and a burst all passes. The gate books an `InteractiveDispatch` seat under the payload's `session_id`, counted by `live_agent_count` alongside the claims: the ceiling path claims one (refused past the ceiling, and the refused row is deleted), the ceiling-exempt onward dispatch records one uncounted-against-the-ceiling so it is at least VISIBLE to the arm that clamps. `handle_subagent_stop_release` (the `hooks/scripts/dispatch_seat_release.py` sibling) hands the seat back on termination, keyed on `agent_id` so a re-fired stop releases at most one; the 30-minute `SEAT_WINDOW` is only the backstop for a release that never arrives. A release failure, an unbootstrappable Django, or any internal error leaves the seat to its window and never propagates.
- **Every `t3` shell-out goes through one seam — a hook must never spawn `t3` itself.** `hooks/scripts/t3_invocation.py` resolves the argv (`t3_argv` / `t3_available`) and runs it (`run_t3` / `spawn_t3_detached`), pinning a cwd the container can see: the checkout this hook package was installed from, derived from the seam's own location and CHECKED against the tree rather than trusted as a constant depth. A hook is started in the SESSION's working directory, and the containerized `t3` entry point REFUSES a directory it cannot see from inside the container — so an inherited cwd makes the shell-out exit non-zero for a reason unrelated to what the hook asked, and a gate that fails CLOSED reads that exit as a DENY on correct work. Pinning that cwd is only half the guarantee: the entry point translates the host cwd against a fixed table of worktree roots, and the hook package's own checkout is absent from it even when the container mounts that tree 1:1 — so the pinned cwd was refused too, and every gate on it failed closed. The seam therefore also exports `TEATREE_INVOCATION_CWD`, the escape the refusal names, for a directory `hooks/scripts/container_visibility.py` PROVES the container reaches: a bind mount whose destination equals its source, read from the CLI service's own mount table. Never assert reachability — a blind `TEATREE_INVOCATION_CWD=$(pwd)` is what lets a `t3` call operate on a tree nobody meant. Every unanswerable case (no docker, no running container, an unreadable table) declares nothing and keeps the refusal. `tests/conformance/test_hook_t3_invocation_seam.py` fails on any `hooks/scripts` module that calls `shutil.which("t3")` or hands a `t3` argv to a raw `subprocess`, so the bug cannot be reintroduced by omission. Pass `cwd=` only when the subject genuinely IS a directory (`coverage_gate`'s measured repo); an unresolvable checkout fails LOUD — one stderr line, the call still proceeds — never closed and never silent.
- **The dispatch brief is linted for unanchored factual assertions ([#4341](https://github.com/souliane/teatree/issues/4341)).** `handle_brief_anchor_lint` (`PreToolUse`, `Agent`/`Task`, the bare sibling `hooks/scripts/brief_anchor_gate.py`) fires when a brief BOTH asserts verifiable specifics — a `file:line`, a SHA, "there are N", "X does not exist", a `SCREAMING_SNAKE` config key — AND anchors none of them: no verification-word-plus-SHA ("verified at `<sha>`") and no trust-the-code clause. Orchestrator briefs asserted ~23 disconfirmed premises across two sessions; the countermeasure that caught every one was the sentence the warning quotes verbatim, and it works precisely because it needs no knowledge of WHICH assertion is stale — so neither does the lint. It WARNS to stderr and returns falsy by default (the fleet dispatches constantly; a false deny costs more than an ignored line); `brief_anchor_gate_refuse = true` flips it to a deny routed through `_fail_open_or_deny`. The detector is `teatree.hooks.brief_anchor_scanner`, deliberately conservative on the no-fire side: a SHA shape needs a digit AND a letter (English words spell fine in the hex alphabet), a config key needs an underscore (so the `NEVER`/`ALWAYS` imperatives every brief carries are not keys), and fenced blocks are excluded — a pasted command is an example, not an assertion. Never-lockout: the warn default cannot deny, the per-call `[brief-anchor-ok: <reason>]` token (first 512 chars), the `[teatree] brief_anchor_gate_enabled = false` kill-switch (`t3 <overlay> gate brief-anchor disable`), `_fail_open_or_deny`, and an unimportable `teatree` or ANY internal error failing OPEN.
- **Hooks must be crash-proof and fast.** `hooks.json` sets a 30s timeout ceiling; a hook that raises or hangs blocks the user, so stay fast regardless of the ceiling. Fail open and stay silent on the happy path.
- **That ceiling is a budget SHARED by every shellout a handler makes, so a second one asks `hook_budget` what is left ([#4305](https://github.com/souliane/teatree/issues/4305)).** Overrunning it does not truncate the last call — the harness cancels the hook, so NO `permissionDecision` is emitted and the guarded command proceeds past a gate that had already refused it. Gate 12 is the case: `coverage_gate` shells the `t3 tool diff-coverage` measurement and then, on a finding, `existing_artifact` shells the `t3 tool open-pr` probe, whose fixed timeouts summed to 45s. `hook_budget.bounded_timeout_s(preferred, elapsed)` shrinks a request to what the ceiling still affords and answers `None` once the budget is spent, so the caller skips a subprocess it would only be cancelled inside of; `HOOK_CEILING_S` mirrors the `hooks.json` PreToolUse `timeout` and is pinned to it by `tests/test_hook_budget.py`. A handler that spends budget stamps `time.monotonic()` at its own entry and passes the elapsed down — the probe's skip is one more of `open_pr_note`'s unanswerable cases, so the deny still goes out, undecorated.
- **Statusline state** is regenerated, not authored: `/tmp/claude-statusline/<session>.<suffix>` (override dir via `TEATREE_CLAUDE_STATUSLINE_STATE_DIR`). Never read it as a source of truth.
