# tests — local conventions

See the root [`CLAUDE.md`](../CLAUDE.md) for the code-quality bar. This file adds only what is specific to `tests/`.

- **Run:** `bash dev/test-affected.sh` for the inner loop — the diff-scoped lane, parallel (`-n auto`), no coverage. It is the default because a local whole-tree sweep just pays again for what CI's required sharded lane is about to run ([#3994](https://github.com/souliane/teatree/issues/3994)); the lane escalates to FULL itself on anything it cannot prove local, and `--full` forces the whole suite for a genuinely cross-cutting change. A single node while iterating: `uv run pytest tests/<mirror>/test_<leaf>.py -q --no-migrations --reuse-db`. The full coverage gate (`bash dev/test-cov.sh`, and the CI `test (3.13)` lane) is **93% branch, non-negotiable** (`fail_under = 93, branch = true`; migrations omitted). New code ships with its tests in the same commit.
- **Before pushing a src-touching PR, run `bash dev/ci-parity-fast.sh`** — scoped prek, `makemigrations --check`, the affected-tests lane, and the incremental push gate (NO coverage floor). It is necessary and sufficient locally: CI's required, sharded `test (3.13)` lane owns the whole-tree floor, and duplicating it locally buys nothing but wall-clock. `bash dev/ci-parity.sh` is the opt-in deep lane — the exact full CI predicate (prek, `makemigrations --check`, `t3 tool test-path-mirror`, `check_module_health.py --from-ref`, `dev/test-cov.sh`, `t3 ci coverage`) — for reproducing a red CI or a coverage-sensitive PR. The push-stage `ci-critical-parity` hook runs `dev/push-gate.sh` — the fast early signal (the never-lockout contract + the `tests/conformance` lane + the incremental push gate `t3 tool push-gate --run`: scoped doctest + ast-grep, FULL on any uncertainty, behind the default-TRUE `incremental_push_gate` flag — ON scopes the diff, OFF is the pre-#122 whole-tree run). The broad `tests/quality` dir is CI-only (~420s locally even with `push_heavy` deselected; the `test (3.13)` shard covers it whole-tree). `tests/conformance` deliberately is NOT: a conformance assertion's input is the WHOLE tree (a new `ScanSignal` kind with no dispatch route breaks `test_signal_route_totality.py` whichever module the diff names), so no diff-scoped lane can prove it unaffected — 34s at `-n auto`, bounded, and it reached CI twice ([#3787](https://github.com/souliane/teatree/pull/3787), [#3788](https://github.com/souliane/teatree/pull/3788)) on green local runs before it went on the push path. The whole-tree coverage floor is provable only by the full lane, so it stays opt-in, never a push hook (`tests/test_no_full_suite_on_pre_push.py`).
- **The order-dependence (shuffle) lane runs locally via `bash dev/test-shuffle.sh`** (seed 7 by default; pass seeds to walk CI's `7 1 13 100` matrix). `pytest-randomly` is out of the default `dev` group on purpose, so a hand-rolled `uv run pytest -p randomly … | tail` raises a plugin ImportError while the PIPELINE exits 0 — a lane that collected nothing reads green. The runner installs the group, preflights `import pytest_randomly`, passes `-o required_plugins=pytest-randomly`, and never pipes pytest. `tests/test_ci_shuffle_lane_scope.py` pins each guard and the directory parity with CI's `test-shuffle` job.
- **The CI `test (3.13)` gate is sharded, the floor is not weakened.** CI runs a 12-way `test-shard` matrix (`pytest-split`) that measures coverage with no floor, then a `test` COMBINER aggregates the shards, proves an exact partition (`scripts/ci/check_shard_completeness.py`), and enforces the 93% floor once over the combined data — identical semantics to the single-process `dev/test-cov.sh`. `tests/test_coverage_floor_guard.py::TestShardedCoverageLane` locks that the floor stays load-bearing (needs-edge to the shards, ≥2 distinct groups, partition check, shard-pass guard).
- **Tests mirror `src/`.** Test path mirrors the module under test; classes/methods describe behaviour, not implementation.
- **Pin the loop principal with `tests._loop_principal_env.pinned_loop_principal`, never `mock.patch` on the resolvers.** `mock.patch` restores only the attribute it replaced, never the copies other modules already took — and Django imports management commands lazily, so a patch live during such a module's FIRST import stamps the `MagicMock` in permanently and poisons every later test in the same xdist worker (souliane/teatree#3810: `t3 <overlay> handover whoami` reporting a loop test's session id). `teatree.loop.session_identity` delegates on every call, which closes that door for `teatree.core.session_identity` patches but NOT for patches of the loop entry point itself — `handover` still binds off it with a module-level `from ... import`. The env seam replaces no attribute at all, and is hermetic against an ambient session or runner principal.
- **Lean integration / functional.** Prefer the Django test client, `call_command`, and real `git` under `tmp_path`. Reserve unit tests for pure logic (parsers, formatters, branch-name builders). Mock only unstoppable externals (network, clock, third-party subprocesses). Full rule + review gate: `AGENTS.md` § "Test-Writing Doctrine".
- **A regression test must be observed RED before the fix.** A test that passes on the buggy code guards nothing — see `/t3:code` § TDD Discipline.
