# Memory Consolidation — the idle-time "dreaming" pass

> BLUEPRINT §4 appendix. The idle-time memory-consolidation ("dreaming") data layer and phase mechanics, split out of the top-level BLUEPRINT so §4 keeps the architecture and this file holds the depth. Cited as `BLUEPRINT §4` from `teatree.loops.dream`.

**Memory-consolidation data layer ([#1933](https://github.com/souliane/teatree/issues/1933)).** Three durable rows back the idle-time "dreaming" pass that clusters session feedback and distils each cluster into one imperative rule. `ConsolidatedMemory` is the consolidation ledger (the DB row is canonical state + audit trail; a rendered topic file is the output), idempotency-anchored on a sha256 `cluster_key` and owning its status ladder `CANDIDATE → VERIFIED → PROMOTED` (plus `SUPERSEDED`/`EXPIRED`); it refuses an uncited rule, refuses to silently expire a BINDING row, and gates index-line pruning on a terminal status with a recorded durable home. Each rung is written by the pass, not by hand: a cited cluster is recorded VERIFIED (the grounding guard already proved the citation present in a cited snippet, so a second trust step would assert nothing), a re-cluster covering an untriaged row's whole member set SUPERSEDES it — a widened cluster gets a new `cluster_key`, and without this the narrow row sits in the triage queue beside it — and the merged fix of a core gap PROMOTES the rule into that fix's home and EXPIRES the prose (`ConsolidatedMemory.retire`). A `USER_SPECIFIC_KEEP` row stays VERIFIED for good: its lesson lives in the memory file itself, so homing it would authorise decay to archive the only copy. Only PROMOTED and EXPIRED count as a durable home for the rail: a SUPERSEDED rule's lesson lives in its replacement, which has to land first.

**Pass 2 — memory→fix-and-merge ([#2426](https://github.com/souliane/teatree/issues/2426), [#2663](https://github.com/souliane/teatree/issues/2663), [#4776](https://github.com/souliane/teatree/issues/4776)).** A `disposition` ladder (`UNTRIAGED → USER_SPECIFIC_KEEP | (CORE_GAP_NEEDS_TICKET → TICKETED → RESOLVED_RETIRED)`) makes the ledger a queue that DRAINS, not a pile that grows: a generic/teatree-core memory is a confession that core has a workflow gap, so `teatree.loops.dream.promote_memory` triages each untriaged row (injected `MemoryClassifier`, default the `durable_destination` one GROUNDED against the core checkout via `teatree.loops.dream.destination` — a home the tree has a real place for (an existing path, or a new file in an existing sub-directory), OR a curated memory file (`memory/<slug>.md`, `DestinationVerdict.is_memory_reference`), is core-generic; `DestinationVerdict.groundable` (`in_core_tree` OR `is_memory_reference`) is the test triage/promotion actually read, not `in_core_tree` alone — every OTHER destination stays user-specific memory. Before #4776 a memory-shaped destination was treated as ungrounded and kept as memory forever: 49 of 49 gaps measured on one pass were withheld this exact way, so a memory-destined gap now promotes instead. A prefix match alone ticketed invented paths and missed real ones under `evals/`/`hooks/`/`tests/`). The grounding is re-checked at the promotion chokepoint, because the `needs_ticket()` drain promotes rows a prior pass classified without re-running the classifier. When no core checkout resolves (a non-editable install) the pre-grounding prefix predicate decides and says so, rather than silently classifying every core path as memory. The promote verb no longer files a fresh `needs-triage` issue per gap — those PILED UP because the intake scanner SKIPs `needs-triage`. Instead each core gap is QUEUED into the pass's shared `teatree.loops.dream.batch_promote.PromotionBatch` (`PromotionBatch.consider`, deduped by `cluster_key` against every pending gap and every live host; banned-term + bare-reference scanned so a public title never leaks), and `batch_promote.promote_batch` appends the pass's gaps to the umbrella host ticket's `extra.dream_gap_pending` (the ticket for the `dream_umbrella_url` setting) — a pass mints ZERO tickets. A non-empty ledger nudges the backlog sweep, which folds each gap into the best EXISTING host exactly as it groups issues, through `t3 <overlay> ticket attach-gaps` (`loops.dream.gap_attach`): the gap's substance, with its level-1 and level-2 headings demoted, is appended to the host issue's description through the issue-write facade (`core.issue_hygiene`: our tickets only, scrubbed, confirmed on the forge, counted against the sweep run; a terminal host is refused before any write) and its fold — heading and body — re-read before the host records it in `extra.dream_gap_batch`, gains a rubric criterion that blocks its merge until every gap carries a disposition (`t3 dream gap-disposition … --citation | --reject`), and, if unplanned, is routed to planning with the gap list as its intent. A gap no host fits is attached to the umbrella ticket itself; `t3 dream gap-coverage` proves every gap has exactly one owner. The new `CodeHostBackend.update_issue(issue_url, body)` extension method edits the umbrella body in place (GitHub `PATCH .../issues/<n>`, GitLab `PUT .../issues/<iid>`). When a host reaches MERGED, `batch_promote.reconcile_batches` retires the prose (checking the umbrella checkbox first for a batch ticket minted before the sweep, which carries `dream_umbrella_url`) (`RESOLVED_RETIRED`, archived) — through the existing `retire_resolved_memories` (driven off the Ticket's authoritative MERGED state via an injected `is_resolved` predicate, not a fragile forge re-read of a `/pull/<n>` URL) — ONLY for the gaps recorded as DELIVERED (`ticket.extra['dream_gap_claimed_delivered']`, intersected with the ticket's own manifest); an undelivered gap's checkbox stays unchecked and the next pass's `consider()` re-offers it. `promote_batch` stamps each queued gap's row `TICKETED` with a promotion anchor on the umbrella url in the same transaction that queues it, and `_promote_one_gap` stamps a row already riding an unreconciled ticket (`covering_ticket`), so a promoted gap leaves `needs_ticket()` instead of being re-drained every pass; that promotion-time url (`umbrella_ledger.is_promotion_anchor`) is replaced on delivery by the merged PR's url, or by the MERGED ticket's own url when it has no merged PR row (batch retirement is keyed on each confirmed gap's cluster key, because that anchor is shared by every row on the batch, and a partially confirmed ticket on its anchor retires nothing), and a gap a merged host neither delivered nor rejected returns to `CORE_GAP_NEEDS_TICKET` (`ConsolidatedMemory.reopen_core_gap`) unless the gap ledger shows another live owner — decided from the ledger, never from the row's url, because a folded gap's row still carries the umbrella's promotion anchor. A rejected gap stays owned by its host. `t3 dream gap-coverage` reports any TICKETED row on a promotion anchor that no owner holds as stranded. Retirement also DELETES the memory's source `.md` file(s) under a discovered `~/.claude/.../memory/` dir (`delete_source_memory_files`, verified by re-reading the path) — "memory must tend to zero" — before the DB row retires; a row whose file cannot be confirmed deleted stays TICKETED and retries next pass. **No new model:** the pending ledger and each host's `extra.dream_gap_batch` live on existing `Ticket` rows, beside each gap's `ConsolidatedMemory` entry. Legacy per-gap tickets scheduled before #4776 (`extra.dream_gap_key`) keep draining through the unchanged `umbrella_ledger.reconcile_merged_gaps`. A BINDING row is PERMANENTLY exempt from both file deletion and DB retirement — hand-flagged doctrine this pipeline never unilaterally judges "done". Pass 2 queues the gap (durable, reversible) but never hand-implements; it is **default ON** behind the `[loops.dream] memory_promote` / `T3_DREAM_MEMORY_PROMOTE` toggle (flipped from default OFF by [#4685](https://github.com/souliane/teatree/issues/4685)/[#4776](https://github.com/souliane/teatree/issues/4776) — batching is the safety mechanism the inert rail was missing), so an explicit opt-out is the only way a pass skips triaging, upserting, or scheduling.

**Backlog-sweep manifest.** The umbrella pending ledger carries each gap short, scanned title; the backlog sweep reads the corresponding `ConsolidatedMemory` rows by `cluster_key` in one query and puts each full rule, verified citation, and durable destination in the coding task context. The public umbrella checkbox carries only the short title.

**Phase 3c — the Instruction-Compliance Accountant ([#2663](https://github.com/souliane/teatree/issues/2663)).** Instruction compliance is the root KPI: a rule was PRESENT/AVAILABLE (a durable memory, a loaded-skill rule, a CLAUDE.md clause, a system gate, or an explicit in-session directive) and the agent acted against it. `teatree.loops.dream.compliance` mines one pass's extract (reusing `transcript_extract.looks_like_user_correction` as the ground-truth signal) into typed `ComplianceFinding`s — and a `{"role": "user"}` decoded line means a HUMAN typed it, because `decode_transcript_line` tags relayed tool output `tool_result` and an `isMeta` harness turn (Stop-hook feedback, the local-command caveat) `harness`, which the one `transcript_extract.is_human_user_turn` predicate every user-turn keeper asks then excludes from the correction / ask / repeated-turn universes; keyword `TRANSCRIPT_SIGNALS` keeping stays role-agnostic, so a gate BLOCK / DENIED reason inside a tool result still reaches the distiller under its own tag (measured over the 80 newest transcripts: 935 surviving corrections → 45, with all 45 genuine typed corrections preserved) — a correction overlapping a memory-backed rule already on disk is a RECURRENCE (`rule_source=MEMORY`), one with no backing memory a first-occurrence `IN_SESSION` violation — and persists one `InstructionComplianceSnapshot` per pass (`instructions_observed`/`violations`/`compliance_rate`/`recurrences_count`) plus one `InstructionComplianceRecord` audit row per violation. **The binding escalation rule:** a recurrence (a rule that already had a durable memory, violated AGAIN) must escalate to a gate or an eval, NEVER another memory — the pass records the recurrence rather than filing one, and `write_clusters` reclassifies a MEMORY_ONLY cluster whose rule already shows a recurrence off its memory destination to a core-gap home rather than re-promoting another memory. Compliance measurement runs on every pass (tick and run), persists a snapshot, and never files a ticket. Recurrence classification remains available for review. `t3 dream compliance show` prints the latest snapshot (rate + recurrence count + open escalations).

**Every promotion phase is reachable from the cron `tick`, and one pass produces NO ticket** ([#4176](https://github.com/souliane/teatree/issues/4176), [#4776](https://github.com/souliane/teatree/issues/4776)). Eval derivation and live validation run on every pass. `--full` (`PipelineMode.force_all_phases`) adds the optional core-gap ticket phase for one manual pass; nightly `tick` also reaches the eval phases. Pass 2's gating and the compliance phase's fault-isolation live together on `teatree.loops.dream.gap_phases.GapPromotionPhases`, composed onto the command through a `backlog_host_resolver` exactly as `phase_runner.MemoryPhaseRunner` is. Each phase used to schedule a real coding task PER GAP through `umbrella_ledger.promote_gap` — one gap, one ticket, one PR — rationed by a `promotion_cap` (a `PromotionBudget` class, formerly in `teatree.loops.dream.pass_config`) that bounded how many of a pass's gaps got a ticket without bounding the fan-out itself: a measured pass with 297 pending gaps and the cap-of-5 default deferred roughly 60 nights to drain. `promotion_cap`/`PromotionBudget` are DELETED ([#4776](https://github.com/souliane/teatree/issues/4776)): Pass 2 now COLLECTS its gaps into one `teatree.loops.dream.batch_promote.PromotionBatch` shared for the whole pass (`GapPromotionPhases.run_memory_promotion` takes `batch=`, not `budget=`), and `batch_promote.promote_batch` queues every collected gap on the umbrella host's pending ledger once every phase has run — a pass with 300 gaps mints no ticket and schedules no task; the backlog sweep folds them into existing hosts. Only the DELIVERED subset a coder/reviewer records (`ticket.extra['dream_gap_claimed_delivered']`) gets its umbrella checkbox checked and its memory retired (`batch_promote.reconcile_batches`); an undelivered gap stays unchecked and the next pass's `consider()` re-offers it — a batched PR that claims more gaps than it delivers can never silently tick the ones it dropped. Legacy per-gap tickets scheduled before this shipped keep draining through the unchanged `umbrella_ledger.reconcile_merged_gaps`. `PassBudget` (the WALL-CLOCK axis) is unrelated and unchanged.

**Manifest evidence filter.** The backlog-sweep task places `DREAM_BATCH_MANIFEST_HEADER` after its directive and directly before the gap lines. Transcript extraction drops a line carrying that header before selecting high-signal evidence, so the manifest citation cannot be re-ingested as a fresh observed gap.

**Phases 4–6 are LIVE** ([#1933](https://github.com/souliane/teatree/issues/1933) § 6): the cron runs the memory-file phases (cross-link, merge, re-index, decay) over the discovered `~/.claude` memory dirs, each fault-isolated in its own try/except so one phase (or one dir) failing never crashes the tick or stops the others, and each runs on every pass. The file-side phases run independently of the transcript extract, so they fire even on a 0-transcript-member pass (which stays attempted-not-succeeded for consolidation, but still re-indexes/decays the on-disk memory set; [#2547](https://github.com/souliane/teatree/issues/2547)).

**Phase 4** (`teatree.loops.dream.cross_link`) appends symmetric `[[name]]` wiki-links between related memories — related when their significant-token Jaccard clears a deterministic floor (no model) — and is idempotent (a re-run on an unchanged set adds nothing).

**Phase 4b** (`teatree.loops.dream.merge`, [#2723](https://github.com/souliane/teatree/issues/2723)) is the on-disk MERGE verb cross-link was missing: it collapses a near-duplicate PAIR (body-token Jaccard ≥ 0.85 AND same frontmatter `type`/`name` family — far above cross-link's floor) into the HIGHER-WEIGHT survivor (a BINDING rule outranks a plain restatement, so binding doctrine is never the side absorbed), appends the absorbed file's distinct lines with a provenance header, and ARCHIVES the absorbed file via `decay._archive_one` (moved, never deleted) so the re-index drops its pointer in the same pass.

**Decision-3 (binding):** two BINDING near-duplicates are NEVER auto-merged — they are cross-linked and ONE deduped reconciliation gap per pair is queued on the umbrella host's pending ledger (`loops.dream.binding_reconcile`, reusing the banned-term / bare-reference withholding), so the backlog sweep folds it into an existing host where a human records which rule is canonical — the pass files no forge issue. Phase 4b runs AFTER cross-link, BEFORE re-index, always runs and is fault-isolated. The whole file-side phase orchestration (4/4b/5/6 + the § 4 gates) is a composed `teatree.loops.dream.phase_runner.MemoryPhaseRunner`.

**Phase 5** (`teatree.loops.dream.reindex`) regenerates `MEMORY.md` as one tight line per memory — a single bare `- name.md` pointer with no free-text summary, since at a realistic corpus even a 45-char hook pushes the index over the gate-(d) byte budget while the descriptive filename slug already IS the hook — deduped, filename-stable, content stays in the topic file, byte-identical on a no-change re-run. The renderer is TOTAL and never caps itself ([#4385](https://github.com/souliane/teatree/issues/4385)): an over-budget corpus renders every pointer and trips gate (d) RED. A self-truncating renderer would make `Gate.index_budget` — which grades the rendered text — structurally incapable of ever failing, and would strand each dropped pointer in NEITHER index, since only archival has a durable destination (`archive/` for the body, the cold index for the signature). Enforcement therefore lives in the budget tier alone. Because the header regenerates wholesale, the generated one carries the load limit and the settled-record rule itself — a hand-curated guidance line otherwise survives exactly one pass.

**Phase 6** (`teatree.loops.dream.decay`) ages a memory out by ARCHIVING it (moved to `<memory_dir>/archive/` with a provenance header, never deleted) — gated by a NON-VACUOUS retention guard that retains a memory when ANY of: it is fresh (mtime within the window), it is still referenced (another live memory or the index `[[name]]`-links it), OR — the **transfer-before-prune rail** ([#2546](https://github.com/souliane/teatree/issues/2546), #1933 § 2) — its lesson has NO confirmed durable home in the `ConsolidatedMemory` ledger. Only a memory that is old AND unreferenced AND durably homed is archived; a guard-disabled probe proves each guard has teeth. The §2 rail — *"delete an index line only after the fact has a confirmed durable home in a topic file"* — is applied to the topic file itself: an injected `HomeResolver` seam keeps the file-side mechanics DB-free under test, while the production `ledger_durable_home_resolver` reads `ConsolidatedMemory.objects.prunable()` (the index-pruner's terminal-status + recorded-`durable_destination` surface) once per pass and maps a topic file to a row by path membership in `source_files` OR by its name appearing in a `durable_destination`.

**Budget RETIRE tier ([#2723](https://github.com/souliane/teatree/issues/2723)).** The `prunable()` home-rail is structurally EMPTY for the hand-authored corpus (0 ledger rows reference on-disk memories), so it can never archive the files that bloat the index. A second, ledger-INDEPENDENT tier (opt-in via `DecayPolicy(budget_tier=BudgetTier())`, enabled in the cron) fires when `MEMORY.md` is over EITHER gate-(d) load budget — bytes or lines, one shared `over_budget` predicate so the decay-pressure trigger and the grading gate can never disagree, and so line pressure is relieved even when byte headroom is comfortable ([#4057](https://github.com/souliane/teatree/issues/4057)) — and then drains to the strictly LOWER `INDEX_LINE_DRAIN_TARGET` / `INDEX_BYTE_DRAIN_TARGET` ([#4385](https://github.com/souliane/teatree/issues/4385)). The budget is the CEILING gate (d) grades; the target is where decay STOPS, and the gap between them is deliberate hysteresis: draining to the ceiling landed the index on exactly 200 lines, so the first memory written after the pass truncated the tail and it stayed truncated until the next nightly pass, while gate (d) — which grades once, immediately after the pass — reported PASS. Firing on the target too would archive a file a night forever, undoing #2755's "don't archive for nothing". Candidates are ordered SETTLED-HISTORY-FIRST (`decay_signal.is_settled_ticket_record` — a `ticket-<n>-…` record; the number is REQUIRED, so `ticket-plan-…` standing rules are not swept up), then LOWEST-`signal_score` within each tier — scoring each by user/BINDING weight, inbound `[[name]]` links (+40 each), a LOGICAL `lesson_updated` recency clock (NOT raw `st_mtime`, so a cross-link / re-index rewrite does not reset it), and a per-type floor. Signal ALONE inverts on the real corpus: the uncapped cross-link fan-out makes the resolved per-ticket records a mutually-citing clique worth ~+1200 of inbound-link signal each, ranking every one of them above an uncited durable rule, so a lowest-first walk archived the standing rules the index exists to surface and left the settled history hot. The predicate fails CLOSED toward retention — anything it cannot classify keeps its normal score. Referenced entries are NOT hard-retained ([#2753](https://github.com/souliane/teatree/issues/2753)): the cross-link phase runs BEFORE decay and references most of the corpus, so a hard skip floored the tier above budget and it could never converge; the +40-per-link signal instead ranks referenced entries HIGHER so they are archived LAST, only when the budget genuinely forces it. Every archived entry stays restorable in `archive/` (full body + provenance) and recall-able via the cold `MEMORY_ARCHIVE.md` signature, so a now-dangling `[[link]]` in a surviving body is cosmetic, not data loss (the hot index uses bare `- name.md` pointers, which never dangle); the conservative stale/ledger tier keeps its reference skip. The cron re-indexes AFTER this decay so `MEMORY.md` falls back under the gate-(d) budget in the SAME pass. All phases accept an explicit `memory_dir` and never touch the real `~/.claude` under test.

**Cold-tier RECALL ([#2746](https://github.com/souliane/teatree/issues/2746)).** The budget tier moves the lowest-signal memories — ~130 BINDING/Non-Negotiable rules of a ~693-entry corpus — to the NOT-session-loaded cold `MEMORY_ARCHIVE.md`, so they stop influencing behaviour. The `PostToolUse` hook `hooks/scripts/owner_turn_context.py` closes that gap: on the first tool call after an owner prompt, the DB-free, stdlib-only pure core `teatree.loops.dream.recall` scores each cold-index line against that prompt's tokens (ambient `<system-reminder>`/`<command-*>` blocks stripped FIRST so an injected `MEMORY.md`/`CLAUDE.md` dump can never self-match), applies a 2-match relevance floor BEFORE any BINDING(+3)/`user_`(+2) boost, dedupes against the hot index (pointer name + a renamed-file signature-substring guard), and injects the top ≤5 hits (≤1500 bytes, each line ≤200 chars) for that one turn; the hook is its own process that never imports Django, serves each owner prompt once, and is crash-proof and silent on any degrade or past its 0.3 s budget. `t3 <overlay> memory recall <query>` is the manual-lookup CLI. The recall quality and the §4 retention probe share ONE frontmatter-aware extractor `reindex.signature_text` ([#2746](https://github.com/souliane/teatree/issues/2746) nit-4) — preferring a memory's frontmatter `description:`/`summary:` over the weak `node_type: memory` body line — routed through by `gates._signature_line` (cold index + probe), so the cold index and the retention probe derive the SAME signature — the hot index carries bare `- name.md` pointers and derives none. The shared `_teatree_bool_setting` reader is extracted to the `hooks/scripts/teatree_settings.py` leaf so a gate leaf reads its kill-switch without a `hook_router`↔leaf import cycle.

Two legacy limits remain: retrying an incomplete historical two-gap fold written in reverse order can append a second section, and a complete legacy fold keeps its legacy marker. Both cases leave existing text intact.

**Phase 3b** ([#2346](https://github.com/souliane/teatree/issues/2346)) maps grounded clusters to eval candidates in a JSONL review queue. `teatree.loops.dream.promote` checks each candidate with the real grader against drift and compliant transcripts. A candidate that fails on drift and passes on compliant behavior is queued on the dream umbrella ticket with its scenario and fixture text; the factory writes the files through that ticket's coding PR. The nightly `tick` requests proposals on every pass.

**Phase 3b LLM derivation** ([#2447](https://github.com/souliane/teatree/issues/2447)) is the richer follow-up to the fixed-matcher `promote`: `teatree.loops.dream.llm_eval_proposer` runs an injected LLM synthesizer that turns a grounded candidate plus its cited transcript slice into a COMPLETE `under_load` `EvalSpec` — a pollution preamble saturated to the documented ~28k-char envelope floor, discriminating positive + negative matchers, and a judge rubric — parsed through the real loader and gated by a **candidate-derived** teeth check (`teatree.loops.dream._teeth_check.teeth_check_against_candidate`): it synthesises the `_fail`/`_pass` transcripts FROM the candidate's OWN cited drift and compliant tool-call shapes and grades both through the suite's real grader (`teatree.eval.report.evaluate`), DROPPING a spec whose matchers do not reject the candidate's own cited drift (or reject its compliant shape as a tautology) — proving the matchers target the SPECIFIC drift the candidate describes, not `promote`'s fixed session.py-edit transcripts. Even a proven spec is never autonomously committed to `evals/scenarios`: `stage_derived_evals` writes a staging `derived_evals.yaml` a human / standing core-maker ratifies via a PR. The phase runs on every pass; staged scenarios still require a human or standing core-maker to ratify them in a PR. The `dream` mini-loop is registered `off_live_tick` (driven only by the worker's `drive_off_live_tick_loops` chain firing its `off_tick_command`); `t3 doctor` surfaces the 48h staleness alarm.
