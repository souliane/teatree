# BLUEPRINT Appendix — Global CLI mechanics

Detail behind [BLUEPRINT.md](https://github.com/souliane/teatree/blob/main/BLUEPRINT.md) §8 ("Global CLI"): how the global commands that carry more than a one-line contract work.

`t3 push` ([#3927](https://github.com/souliane/teatree/issues/3927), `core/forge_push.py`) is the ONE supported push path from the worker container — without a named seam every agent improvises, and the two forms it reaches for first are the damaging ones: a bare `git push` from a `docker exec` shell (which bypasses the entrypoint's `GH_TOKEN` export and inherits only `TEATREE_GH_TOKEN`) BLOCKS on git's interactive credential prompt until something kills it, and the "fix" for that writes the token into `remote.origin.url`, persisting the credential in the `.git/config` of a host-bind-mounted worktree where it outlives the session. It resolves the forge-write token through the same chain the loop scanners use (`GH_TOKEN` → `TEATREE_GH_TOKEN` → the overlay's `pass` store → the ambient helper) and hands it to git as env ONLY — never on argv, never written into a remote URL — runs under `utils/git_run.py`'s `git_env_non_interactive()` so a missing credential fails in milliseconds with a hint that distinguishes "no token resolved" from "token supplied but the helper is unwired" (`gh auth setup-git`), REFUSES a remote whose URL already embeds a credential, never passes `--no-verify` (the pre-push hooks still gate the push, after `core/prek_hook.py`'s `harden_hooks` replaces a prek binary another venue baked into the clone's shared hooks, so a host `prek install` cannot refuse every push from the container) and offers `--force-with-lease` but no bare `--force`, and verifies the post-condition against the REMOTE ([#4088](https://github.com/souliane/teatree/issues/4088)) — an rc=0 `git push` only ends the attempt, so the branch counts as pushed once `ObservedRemoteRef.observe` reads it back with `git ls-remote` and finds it at the local tip; `git rev-parse <remote>/<branch>` cannot play that role because the remote-tracking ref is what this clone last HEARD, not what the remote holds, and it answers the empty string when it resolves nothing. Every ref the module reads or writes is FULLY QUALIFIED (`core/forge_push_refs.py`'s `BranchRef.qualified`), the bare name surviving only in the operator-facing report ([#4117](https://github.com/souliane/teatree/issues/4117)): a tag sharing a branch's name makes each bare spelling answer something else — `rev-parse --abbrev-ref HEAD` (and `symbolic-ref --short`) answer `heads/<name>`, which the config check then refuses as a typo; `rev-parse <name>` answers the TAG's sha; and `push <remote> <name>` refuses the refspec as ambiguous BEFORE any hook runs, so the pre-push gate is blamed for git's own refusal. So the checked-out branch comes from plain `symbolic-ref HEAD` (whose non-zero exit is the detached-HEAD case the caller already wanted), and the refspec pushed is the same string the read-back verifies. A ref absent from the remote, a ref at another sha, and a remote that could not be read are three distinct refusals (`not-on-remote` / `remote-sha-mismatch` / `unverifiable`) — an unreadable remote is an unknown and never a success. The endpoint read back is the PUSH url, not the fetch url: `remote.<name>.pushurl` divorces the two, so `RemoteUrls` resolves both — verification targets the push url (the only endpoint whose answer proves anything) while the embedded-credential refusal covers EITHER, since a secret in either persists in `.git/config`. Every refusal carries a `PushFailure` kind and its own exit status ([#4076](https://github.com/souliane/teatree/issues/4076), `PUSH_EXIT_CODES`: 1 transport, 2 repo config, 3 credential, 4 pre-push gate refused, 5 non-fast-forward, 6 not delivered, 7 unverifiable, 8 the remote's own policy declined) so a caller branches on the fix rather than parsing prose, and a refusing pre-push gate is reported with the GATE's own stderr — `GitPushError` strips git's outer `failed to push some refs` commentary, which is true of every push failure and therefore evidence of none, and names the hook when an OOM-killed gate leaves no output at all. That gate verdict rests on POSITIVE evidence (`refused_by_a_gate`: an executable hook AND git's rc=1 AND its aborted-push summary AND no remote contact) — never on the absence of remote-contact lines, which an unreachable network produces too and which would blame the hook every teatree checkout carries for every transport outage. `PushOutcome.exit_code` fails closed: it is never 0 while `ok` is false. `--json` emits the `PushReport` an orchestrator routes on, carrying that kind and code. It is also the ONLY push in the tree: `runners/ship.py`'s `ShipExecutor` (the ship path) and `cleanup/cleanup_salvage.py`'s salvage hook both call `push_branch`, and the retired raw Git synchronization helper they used to reach for is GONE ([#4103](https://github.com/souliane/teatree/issues/4103)) — it ran under the non-interactive env but supplied no credential, so a ship from a `TEATREE_GH_TOKEN`-only venue died on git's own `could not read Username` while `t3 push` beside it worked. A ship push that does not land is a `RunnerResult(ok=False)` carrying that `PushFailure`, never a raised `CommandFailedError`. `t3 fast-push` (directive #8, `core/push/fast_push.py`) is the leak-gated escape hatch for session hand-offs: it stages everything, runs ONLY the four leak gates in-process and fail-closed (banned-terms, the `scripts/privacy_scan.py` secret scan, overlay-leak terms + opaque IDs, and the #730 public-repo commit-author-identity check — the same canonical matchers and DB-home sources as the hook chain, so bypassing the hook chain never bypasses leak protection), then commits, pushes with the hook chain bypassed, and idempotently creates-or-updates the branch PR (`--remaining` records unfinished work as a `REMAINING:` PR-body section). Any finding refuses the push and prints the offending path/term; every non-leak gate (ci-parity, coverage, lint, module-health, tests) is skipped by design. `t3 ui` is a trogon-backed terminal browser of the command tree (optional `ui` dependency group). `t3 admin` runs the Django admin for the teatree project under a local gunicorn server (`teatree.wsgi:application`, a production WSGI server — not Django's dev `runserver`; #3134) — it migrates, collects static into `STATIC_ROOT` (so WhiteNoise serves the admin and dashboard assets with DEBUG off; #3162), ensures a superuser (creating one non-interactively from `T3_ADMIN_USER`/`T3_ADMIN_PASSWORD` when absent), and opens `/admin/`. The same process also serves the first-party `teatree.dash` admin dashboard at `/dash/` ([#3162](https://github.com/souliane/teatree/issues/3162)) — a ticket-FSM kanban (`build_kanban_columns` groups tickets by `Ticket.State`, tasks are card badges), an "is-everything-OK?" health view (over `read_health` / `loops.live.build_report` / parked-lane / utilization / `t3 cost` / queue readers), a UNIFIED loop table ([#3559](https://github.com/souliane/teatree/issues/3559) — one row per loop carrying its effective verdict + deciding layer, cadence, last-run/next-due and held state, with the infra lease slots kept as a small distinct section) whose emergency tier is per-loop pause/resume/disable/enable through the SAME paired `LoopState`/`LoopManager` verbs plus the `danger_gate_fail_open` toggle behind a typed confirm and a READ-ONLY fleet-verdict band naming the active preset and whether it admits anything — the fleet is stopped and restarted by switching posture, never by a second switch on this page, so there is one control surface rather than two that can disagree. Stopping the fleet produces no error and no visible failure, work simply stops arriving, which is why the band states the verdict rather than leaving it to be inferred; restarting the fleet is recoverable and a confirm step there is friction on exactly the path an operator takes under pressure, and both directions are audited through the same `dash.audit.record` seam every other mutating dash POST uses, a per-loop **cadence editor** on that table (interval XOR wall-clock, validated by `loops.loop_cadence_editing` against an absolute floor and the registry cadence floor a self-gating loop declares via `MiniLoop.cadence_is_floor`), a **schedule + preset editor** at `/dash/presets/` (switch the active schedule and the active preset override, edit each preset's tri-state per-loop entries — `on` / `off` / *absent = the base decides*, surfaced as an explicit no-opinion state with the loops it leaves undecided named — create/rename/delete a preset, edit its description, and add/remove schedule slots), every write routed through the `loops.preset_editing` / `preset_admin` / `schedule_editing` seams `t3 loop preset use` / `preset edit` / `schedule set-active` / `schedule set-slot` / `schedule delete-slot` also call; a rename re-points every by-name referrer (override row, schedule slots, preset-selecting settings) in one transaction and a delete is refused while one still names it, and the mode switch refuses a name no `Mode` row carries rather than writing an override that would silently fall open to base config, ONE **settings page** at `/dash/settings/` ([#3664](https://github.com/souliane/teatree/issues/3664), nav item *Settings*) — the merge of the former read-only config page into the editable one, so there is a single surface for what this box is configured to do. Its **live readouts** (`dash.settings_readouts`, on their own 15s htmx poll at `/dash/settings/readouts/`) are the values that are RESOLVED rather than typed, composed from the existing resolvers with no second source of truth: the model & reasoning-effort pins (`resolve_agent_config()` — `session_model`, `session_effort`, `honesty_model`, per-tier model + effort), the credential coordinates (`get_effective_settings()`, matching a credential REFERENCE by suffix so a new one needs no second registration), and the self-repairs (the non-paging surface the #3665 stamp renders on); **no secret value is ever rendered** there — a credential row carries the credential-store entry NAME plus a resolves yes/no (the probe's return value is discarded, never stored or shown) and an entry name that is itself private renders as `<private>` while still reporting whether it resolves, and the readouts fail open like the health page, degrading to a visible error rather than a 500. Every OTHER dial the retired page showed read-only (kill switches, concurrency & memory caps, `agent_harness` / `agent_harness_provider` / `mode` / `wip` / `autonomy`) is an EDITABLE row on the same page instead — and `/dash/config/` now redirects here, its nav entry gone. The editable half walks the pydantic schema (`dash.settings_editor.build_settings_editor`) so every config key is listable with no hand-kept list, GROUPED by `config.setting_groups.group_tree` into a NESTED hierarchy several levels deep (`Gates / Quality / Merge & done`) — membership AND shape DERIVED, never listed: each `UserSettings` declaration base declares its own `GROUP_PATH`, and the base set plus their render order come off `UserSettings.__mro__`, so adding a field to a base places it with zero edits anywhere (a key no base declares is grouped by the registry that registers it, each registry declaring its path beside its own keys); `tests/config/test_settings_group_partition.py` pins the bases pairwise-disjoint and exhaustive over the TREE as well as the flat field set (no two bases claim one path, no path is a strict prefix of another, the leaves partition every field exactly once), and the tree's LEAVES are the page's sections, so a key whose group is unknown — or whose path names a level nothing else declares — lands in a VISIBLE leftovers section rather than vanishing; the dashboard renders ONE leaf per request (sections on the left, the selected section's rows `hx-get` into the right pane — [#3825](https://github.com/souliane/teatree/issues/3825)) while `setting_groups.group_outline` streams the SAME tree as headings + rows for the three text surfaces — `config_setting export`'s `[teatree]` table, the shipped `config/defaults.toml`'s `[teatree]` table (both emitted through the ONE `setting_groups.grouped_settings_table` renderer as real NESTED sub-tables, so the owner-approved `snapshot_settings_defaults --apply` rewrite cannot re-flatten the hand-edited file) and `config_setting list` (indented headings) — the TOML KEYS staying FLAT because that namespace is the persisted contract, `cold_defaults.flatten_settings_table` collapsing the group wrappers back on read, so a nested dump re-imports byte-identically to a flat one. It writes each edit through `ConfigSetting.set_value` (the same seam `config_setting set` uses, so the #258 coercion + #3688 cross-key checks fire), restores-to-default by DELETING the row (the zero-row / `restore = delete row` semantics), gates a safety-posture key behind an extra confirm phrase, and and hands the whole-store transfer to a page of its OWN at `/dash/import-export/` ([#4340](https://github.com/souliane/teatree/issues/4340), nav item *Import / export*) — hosting it here under-stated it, because a dump reaches past the settings store into the `[loops.*]` / `[modes.*]` / `[schedules.*]` seed families, so an import from the settings page could change which loops run and when while reading as "restore my settings". That page STATES its scope up front from `core/config_interchange/scope.py`'s `EXPORT_SECTIONS` — one entry per top-level table, declared off the same constants `document_layout` and `seed_defaults.SEED_TABLES` give the writers, so the copy and the file cannot drift (`tests/teatree_core/config_interchange/test_scope.py` exports a box tuned in every family and asserts the emitted tables against the statement, with the `[backup]` format marker the one named exception) — offers export (secrets withheld, personal included, with the two independent filters whose both-ticked shape is a byte-identical drop-in replacement for `config/defaults.toml`) + import of an UPLOADED file with an `import_toml_to_db(dry_run=True)` preview whose result is ALSO counted per section (`dash/interchange.py`'s `changed_sections`, over the one `section_for_row` canonicaliser), so "12 rows" can never hide the one that changes a loop; the settings page keeps a link to it and `/dash/settings/export/` redirects there with its filters intact; a SECRET value AND its shipped default are masked to `***` in the surface builder BEFORE the row enters the view context (reusing the export withhold taxonomy — `Category.SECRET` / `SECRET_SETTINGS` / credential coordinate / personal identifier), pinned by a Django-test-client test asserting a configured secret never appears in the response bytes; each row ALSO shows the shipped default `config/defaults.toml` ships for that key beside a verdict — `✓ same as default` / `● differs from default` — so an operator sees at a glance which dials this box has moved, with the tier of the resolution chain that actually supplied the effective value (`config.provenance`, walking the resolver's own layer readers — it replaced a near-constant `category` column showing the setting's KIND) carried as the CELL's tooltip rather than a column of its own, with colour never the only signal (a text icon AND words, and both palette tokens computed against every surface in both themes) and a Secret/Personal key (absent from the shipped file by construction) showing no default and no verdict; each cell posts ITSELF on change and answers the edited `<tr>` ALONE to an htmx request (`dash/partials/_settings_row.html`, `hx-target="closest tr"`) so an edit never re-renders the document and the scroll position never moves — the whole row comes back rather than the one cell, because a global write changes what every overlay column inherits — and a refused write answers 400 carrying that same row RE-READ plus its reason, so a failed edit can never leave text that looks saved; its per-overlay SCOPES are the grid's COLUMNS (global plus every registered overlay and every scope already holding rows) rather than a picker the operator switches between, and an import's own tables (`[teatree]` vs `[overlays.<name>]`) decide where each ROW lands. Beside it sits the **comparison page** at `/dash/settings/compare/` (`core.settings.settings_compare` / `settings_compat` / `settings_peers` / `settings_files`) — this box in one grid with every other one, showing what differs and what an import WOULD do with each row; peer and saved-record reads stay read-only, while eligible cells in the local column write through the same setting or seed-interchange seam as their primary editor. Env-pinned, code-pinned, withheld, confirmation-gated, dedicated-editor-owned, locally absent and non-shipped rows remain readings and name their refusal; peer and record cells never render controls. A column arrives by one of TWO routes producing the same `PeerSnapshot`, so there is one set of rules rather than two: FETCHED over httpx from a peer's own loopback-bound `/dash/settings/snapshot.json` through an `ssh -L` tunnel (the `peer_instances` registry; no instance publishes a port, no `ALLOWED_HOSTS` entry, the same `require_loopback_or_staff` gate, and the path derived from the URLconf so the two ends cannot drift) — resolved for the venue by `settings_peers.fetch_target`, because under the deploy stack the fetch runs in a container whose own `127.0.0.1` is not the machine the forward was opened on, and every peer would otherwise read as refused while its forward is up, or LOADED from a saved snapshot file the operator hands to the page's one POST as picked files or pasted JSON — the only route to the three columns a live fetch can never produce (a box whose tunnel is down, a box that is gone, and THIS box as it stood weeks ago). `t3 settings compare` renders that SAME `build_compare_view()` in a terminal (`cli/settings.py` + `core/settings/settings_compare_terminal.py`) — the comparison lives in `teatree.core` precisely so both readers call one builder and neither can drift; it names every configured instance including the ones that did not answer (a box silently dropped reads as agreement between the boxes that did), prints the comparability verdict BEFORE the rows it disqualifies, and groups differences by kind with values first, `--kind` / `--full` / `--json` / `--snapshot` / `--timeout` narrowing, unclipping, machine-reading, loading records and raising the per-peer wait a loaded forward outruns. A loaded column is labelled a RECORD and carries the snapshot's own `captured_at` so it can never read as live; the POST writes NOTHING (in-memory snapshots for that one response) and a document that is not a `teatree-settings-snapshot`, carries an unread `format_version`, is not UTF-8 JSON or exceeds the size limit is refused BY NAME with what was wrong, one bad document never costing the good ones. `t3 peer` is the EXECUTOR for that registry ([#86](https://github.com/souliane/teatree/issues/86)): the page computed each peer's tunnel command and printed it for an operator to paste, which is the workaround — the verb takes a peer LABEL, reads that peer's entry and runs the command it renders, knowing no host of its own. Resolution happens in the CLI (only it reads the control DB) and OPENING is a host act (`deploy/peer-forward.sh`, reached through the same `deploy/t3` handoff `t3 admin` uses), because the transport binaries and their credentials are the operator's and the near end must bind the loopback the fetch means. A port held by something that opens no forwards is REFUSED rather than read through, a live forward is REUSED by the pid teatree recorded rather than duplicated, only a forward teatree opened may be closed, and one that never answers FAILS after a bounded poll. That host hop is GENERIC for an overlay tool leaf (`core/host_hop/host_run.py`): `admin|dashboard` and `peer` are keyed on hard-coded core VERBS, so an overlay whose tool needs the operator's own machine — a binary, a credential, a loopback port, a browser — could not reach it and simply failed in a venue that cannot do the job; an overlay's own tool leaf is keyed on the command SHAPE instead (`tool` as the SECOND word of the invocation, which core's own top-level `t3 tool` never matches), the container half staging a runner + plan that `deploy/t3` carries out and whose exit code becomes the command's, with an EMPTY plan meaning the tool finished by itself. It stages under the TRUE canonical data dir (`PathHelpers.true_canonical_data_dir`), never `data_dir_root()`, because a plan written from inside a checkout lands in the auto-isolated `teatree-worktrees/<hash>/` dir the wrapper never reads and the reaper deletes. `snapshot.json?download=1` is the SAME read-only payload with a filename built from the instance label + capture date (one `core.settings_snapshot` builder, no second copy; `build_snapshot` takes no `include_private` parameter, so the route is structurally incapable of serving a raw secret). An older record stays comparable because the no-opinion rule treats "no row", "no rows in this scope" and "this code never declared the key" as one fact that compares EQUAL, and because comparability is decided across the LIVE columns alone — a record's differing fingerprint is reported at INFO as its AGE, never as drift and never as a blocker. Every page shares one shell: an `<h1>` naming the page, an off-screen-until-focused skip link to `#dash-main`, a labelled nav landmark, and a header chip naming THIS box (`dashboard_instance_label`, falling back to the hostname, so an operator running teatree on several machines can tell two dashboards apart). The shell also guards a focused text field's value through Idiomorph's `beforeAttributeUpdated` callback, without which a polled morph swap assigns the DOM `value` PROPERTY of the focused element — bypassing the dirty-value flag — and resets a cadence field mid-edit; the blunter `ignoreActiveValue` flag is NOT used, because the bundle also consults it to skip morphing the active element's CHILDREN, which freezes the label of the button just clicked so `pause` never becomes `resume` after its own swap. `/dash/transcript/<id>/` answers the bare fragment only to an `HX-Request` and the full page to an ordinary navigation, since the drawer links it with a real `href`. The credential readout's `pass` resolve-probe is cached per entry name, so an open Settings tab no longer GPG-decrypts every configured credential on each 15s poll, and the preset editor builds the full card only for the OPEN tab, so its query plan no longer scales with the preset count. Every mutating POST on the loops and preset pages answers the page BODY to an htmx request (`dash/partials/_loops_body.html` / `_presets_body.html`, `hx-target="#loops-body"` / `#presets-body`, `morph:innerHTML`) instead of redirecting to a full re-render, and `ticket_transition` answers the refreshed DRAWER — redirecting to the board closed the very panel the action lives in, and the board re-renders on its own 4s poll anyway. Each keeps `method`/`action`, so the pre-htmx redirect still works with JavaScript off. A refused write is no longer a plain-text dead end: an htmx client gets the same surface back at 400 carrying its reason (the `htmx:beforeSwap` opt-in that #3760 scoped to the settings page now lives once in the shell), and a no-JS client gets `dash/error.html` — the reason plus the nav and a link back. There is a ticket drawer (a right side panel — slides in, `Esc`/close dismiss, board stays visible) with the per-ticket lifecycle Mermaid, the legal-FSM-transition action menu and an **enqueue-a-task row** ([#4085](https://github.com/souliane/teatree/issues/4085)) — *Scope / Code / Test / Review / Ship now*, each a POST to `dash:task_action` that creates a phase task through `core/models/task_enqueue.py`, the SAME seam `t3 <overlay> tasks create` calls, so prioritising a PR is a click rather than the raw `db query` (PR number → ticket PK) plus CLI call it used to take. The seam's two entry points are the whole design: `enqueue_phase_task` is the CLI's unconditional create (the loop's phase handoff must stay free to re-enqueue), `enqueue_phase_task_once` is the dashboard's, refusing inside one locked transaction while an UNSTARTED task for that `(ticket, phase)` exists — so a double-click reports the queued task instead of adding a second, and the button for a queued phase renders disabled naming it. The drawer offers only the five canonical phases, and the POST re-validates that allowlist, so the endpoint cannot be driven to enqueue an arbitrary phase string. Every BOARD CARD carries the same row cut to the two phases the owner prioritises from the board (*Review now* / *Ship now*), so the common case needs no drawer at all; their enabled state is ONE bounded read of the whole board's unstarted tasks bulk-fetched alongside every other per-card signal, never one read per card, because the board is polled every 4s and an N+1 there is paid at the poll rate (pinned by `tests/teatree_dash/views/test_page_query_pins.py` at two populations). It enqueues WORK and can never record an OUTCOME: no dashboard control creates, alters or satisfies a `ReviewVerdict` or a `MergeClear` — the maker≠checker gate is the one thing standing between the owner and self-merged unreviewed code, so `tests/teatree_dash/test_no_review_outcome_writes.py` walks the WHOLE `teatree.dash` package (an AST pass over imports, lazy `get_model` resolutions and write calls, itself proven anti-vacuous against each shape) rather than pinning the one view that added the buttons. There is also a debug tier (a loopback `ttyd --writable --once` "Debug session" button + an allowlisted-`t3`-command surface). The visual layer is a tea-derived design-token system (`dash/css/tokens.css` — steeped-dark default + porcelain-light via `prefers-color-scheme`/a header toggle, four FSM state hues, a 12px type floor, a 4px spacing scale) that `dash/css/dash.css` and the `/admin/` re-skin (`templates/admin/base_site.html` + `dash/css/admin-theme.css` mapping Django's admin CSS vars) both build on, so `/dash/` and `/admin/` read as one product; the signature is the **FSM rail** — the board's state hues form a connected pipeline (Backlog → Building → Reviewing → Landed, Ignored detached) reused for the column tops, the drawer's transition-history chips, and the token-themed Mermaid. Card and drawer references are clickable and code tokens are monospace ([#3624](https://github.com/souliane/teatree/issues/3624)) — the card's id IS the forge link (`#N` / `!N`, with `stopPropagation` so it opens the forge rather than the drawer) and the drawer heading id likewise, its meta chip carrying the REF rather than the bare word "issue" (a link-only label the reader cannot identify is the anti-pattern `/t3:rules` § "Render the Title Inline, Never a Bare/Link-Only Id" names); `TicketDetail.issue_href`/`issue_ref` come from the same `issue_link` helper the card uses, so there is one derivation, and a synthetic loop key (`scanning-news://…`) yields `("", "")` and renders as plain text, making a dead anchor impossible. `core/code_tokens.py` is the ONE detector for path / dotted-symbol patterns and protected-span stashing, shared by two surfaces that differ only in wrapping — `news_digest.format_code_symbols` backticks for Slack, the `code_spans` template filter emits `<code>` for the dashboard — so the two cannot disagree about what a code token is; URLs are always protected (a URL is both a `/`-path and dotted, so an unprotected rewrite would shred every link) and the filter escapes FIRST so the only markup it introduces is its own `<code>` pair. Server-rendered Django templates + vendored IBM Plex Sans/Mono (mono for ids/numbers) + vendored htmx with idiomorph morph-swapped polling (no innerHTML flash, scroll- and drawer-stable), the loops table showing only the state-valid verb of each pair, loopback-only behind the same `LocalAdminAutoLoginMiddleware` (its prefix gate widened from `/admin/` to also cover `/dash/`); it owns no models and reads the existing selectors as the only source of truth (`docs/debug-runbook.md` documents the host-SSH+tmux break-glass tier). Behavioral coverage the test client cannot reach — htmx swap stability, drawer flows, Mermaid render, loop round-trips, theme toggle — lives in the pytest-playwright `e2e/dash/` lane (a dedicated CI job against `live_server` with `e2e.dash.settings`, outside `testpaths` and the coverage floor; behavioral only, no pixel snapshots). `t3 cost` reports cycle-to-date SDK-equivalent spend vs the monthly Agent-SDK credit from each `TaskAttempt`'s captured cost, alongside the GitHub agentic-workflow ET (effective-tokens) metric ([#657](https://github.com/souliane/teatree/issues/657), `ET = m*(1.0*input + 0.1*cache_read + 4.0*output)`, `core/cost.py`'s `ET_MODEL_MULTIPLIER`) and both totals split per Layer-2 lane (`subscription`/`metered`) so the two-lane cost strategy ([#2565](https://github.com/souliane/teatree/issues/2565)) is observable. An unrecognised model id with no `cost_model_prices` override is billed in a separate `unpriced` bucket (at the opus rate, annotated) instead of being SILENTLY priced as opus; the DB-home `cost_model_prices` key supplies per-model (id-substring → in/out MTok rate) overrides. `CostBreakdown` splits the same dollars three ways — per tier, per Layer-2 lane, and per PHASE (`per_phase_usd`) — and `core/cost_baseline/` holds the committed pre-cutover per-phase distribution (`pre_opus5.yaml`: attempts, median/p95 output tokens, billed input tokens, turns and cost, per phase and per `(phase, model)`) plus `compare_phases()`, which diffs a live per-phase aggregate against it. The phase is the comparison axis because a model cutover changes which model serves a phase, so a per-`(phase, model)` comparison has no counterpart across it. `TaskAttempt` is dominated by park-audit rows carrying no model and no tokens, so every figure is measured over REAL dispatches only; the artifact's `coverage` block records all three candidate real-dispatch predicates separately so the filter choice is evidenced in the data. `scripts/freeze_phase_cost_baseline.py --check` re-derives it read-only (`mode=ro` + `PRAGMA query_only`) and is reproducible because rows are filtered to `started_at < --cutover-at`. `t3 info artifacts <ticket>` is the read-only "find our eggs" report — where a ticket's worktrees/stacks live, its `PlanArtifact` rows, each `Task.result_artifact_path`, and its `E2eMandatoryRun` evidence (aggregated by `Ticket.artifacts()`, no new storage). `t3 overlay install <name>` editable-installs a sibling overlay checkout into a teatree feature worktree — refuses to run in the main clone.
