# BLUEPRINT Appendix — Headless executor and the dispatch lane

Detail behind [BLUEPRINT.md](https://github.com/souliane/teatree/blob/main/BLUEPRINT.md) §5 ("Headless executor" and "Cached-prefix stability on the dispatch lane").

## The executor and its harnesses

For a read-only Codex phase, the worker gathers forge and survey facts before opening the executor.
Pull request URLs use the PR body and conversation APIs. A manually queued planning task records a
missing landscape survey with its ticket overlay before creation. If required skill text exceeds the
96 KiB system-context cap, complete skill blocks continue in the task message; skill assurance checks
both surfaces. Before each live attestation, the writable worker repairs Git metadata permissions only
inside the checkout mounts shared with the executor, and the isolated probe reports every remaining
unreadable path.

**Headless executor (`src/teatree/agents/runner.py`).** Drives the agent in-process behind the `Harness` seam (`src/teatree/agents/harness.py`) — a REAL-environment run, with the resolved phase model, the worktree `cwd`, and — for a task TYPED as a continuation (`Task.session_continuation`: a `needs_user_input` resume carries its parent's conversation, a retry reopened in place carries its own) — that session via the SDK `resume=` option (`agents/session_lineage.resume_session_id`, the same lineage `agents/pydantic_ai_resume` reads for the metered lane). Phase equality decides nothing: `spawn_child_tasks` mints ordinary same-phase children that each start fresh, and a requeue adopts its own conversation only once it durably has one, so a resume that died before the harness opened keeps the answered lineage it was queued with. A task that begins a new phase starts a fresh session and reads its predecessor's complete `TaskAttempt.result` and artifact paths from a handoff file `agents/phase_handoff` renders from the DB for that one dispatch — a 0400 file in a randomly named 0500 directory under a data-dir `handoff/` store the owner cannot list (0300), removed when the run ends, named after the context budget is applied, and granted (that directory alone) to the `claude_sdk` spawn through `add_dirs` and to Lane B as a read-only root; the inline summary is only a pointer; the honesty escalation resolves independently against every `(session, task)` pair in its lineage (`honesty_subject`), matching a session-wide row or one scoped to that ancestor task, so a fresh reviewing session still routes to the most-honest model when an earlier session escalated. The **transport switch (`agent_harness`, [#2565](https://github.com/souliane/teatree/issues/2565)).** `resolve_harness()` reads the DB-home `agent_harness` setting and returns the backend that opens the session behind the narrow `Harness`/`HarnessSession` protocols (`open` / `query` / `receive_response` / `interrupt`): `claude_sdk` (default — the `ClaudeSdkHarness` wrapping `ClaudeSDKClient`, byte-identical to before the seam) | `pydantic_ai` (the `PydanticAiHarness`, [#2885](https://github.com/souliane/teatree/issues/2885) — a `pydantic_ai.Agent` targeting OrcaRouter's BYOK, OpenAI-compatible, metered endpoint via `OpenAIChatModel`/`OpenAIProvider`; `PydanticAiHarnessSession` adapts the streamed output BACK into the same `claude_agent_sdk` `AssistantMessage`/`ResultMessage` vocabulary `ClaudeSdkHarness` yields, so `runner.py`'s driver never special-cases the transport). **Lane-B tool layer ([#2512](https://github.com/souliane/teatree/issues/2512)).** A PHASED `pydantic_ai` dispatch (`resolve_harness(task, phase=…)`, threaded from `run_agent`) wires the phase-scoped, gated tool/MCP layer (`agents/lane_b`) onto the `Agent` (`toolsets=`/`tool_timeout=`) — otherwise the un-phased harness stays text-only, byte-identical to before the port. Adopts pydantic_ai's OWN native primitives (`FunctionToolset`/`CombinedToolset`/`FilteredToolset`/`WrapperToolset`/`approval_required`/`MCPServerStdio`/`FunctionModel`): teatree-owned File System (read/write/edit/search, worktree-jailed against path traversal; the read tool also reaches an absolute path under the spawn's `add_dirs`) and Shell (denylist/timeout, via `teatree.utils.run`, with the combined output bounded head+tail to `LaneBToolConfig.shell_max_output_bytes` — DB-home `agent_shell_max_output_bytes`, default 16 KiB, `0` uncapped — because an oversized return is re-sent on every LATER request of the thread; the command always runs to completion and the elided middle is named and re-obtainable) capabilities, phase-scoped by the shared `core/modelkit/phase_tools` least-privilege table (keyed on teatree's provider-neutral capability names, which each lane maps to its model-visible vocabulary at its own boundary: Lane B names its `FunctionToolset` tools with the skill/SDK vocabulary — `Bash`/`Read`/`Write`/`Edit`/`Grep` via `agents/lane_b/tool_names` — so a skill instruction saying `Bash`/`Read` names the actual tool, and Lane A's headless `_build_options` injects its COMPLEMENT as `ClaudeAgentOptions.disallowed_tools`, mapped from teatree's capability names to the SAME SDK tool names by `agents/sdk_tool_map` — on top of the unconditional external-contact FLOOR (`_runner_options._EXTERNAL_CONTACT_BUILTINS` — `AskUserQuestion`/`Monitor`/`PushNotification`/`RemoteTrigger`/`SendMessage`) denied on EVERY headless phase, so no headless agent can reach the user or an external endpoint via a built-in (the only sanctioned user-contact path is `needs_user_input` → `DeferredQuestion` → Slack DM; the floor names no capability tool, so a work phase keeps Read/Write/Edit/Bash, and the #116 reader denies the full `KNOWN_BUILTIN_TOOLS` superset) — so a verdict-producing review-phase dispatch (`phase_tools.VERDICT_REVIEW_PHASES` — `reviewing`/`codex_reviewing`/`codex_adversarial_reviewing`/`e2e_reviewing`, one shared grant so the entries cannot drift apart) keeps the shell it needs to cold-check-out the head and RECORD its verdict, while denying `Write`/`Edit` and the spawn tools so it terminates at that verdict, while a write phase's empty complement leaves its disallow list at the floor; the teatree MCP server's writes are a capability of their own — `mcp_write`, held only by `coding`/`testing`/`e2e`/`debugging`/`shipping`/`architectural_review` — so every other phase launches `t3 mcp serve --read-only` (`requesting_review` adds `--allow-write review_request_post`, the one tool that posts its request), and every headless spawn sets `strict_mcp_config` so only that injected server loads); a `HardDenyToolset` consulting the SAME `core/gates/main_clone_guard` + `hooks/quote_scanner` functions Lane A's PreToolUse hook wraps, so a hard-deny (main-clone mutation, privacy leak) fires IDENTICALLY on both lanes; the native `approval_required` deferral for the soft ask-gate; teatree's read-only MCP server as an `MCPToolset` (guarded on the `fastmcp` extra, degrades to none when absent); and context compaction (`compact_history`) trimming `message_history` before each turn. `PydanticAiHarnessSession` maps each turn's `ToolCallPart`/`ToolReturnPart`/`RetryPromptPart` into the same `ToolUseBlock`/`ToolResultBlock` vocabulary the `claude_sdk` lane yields, so tool calls flow through the seam un-special-cased. `agent_harness` is paired with the Layer-2 credential setting **`agent_harness_provider`** ([#2887](https://github.com/souliane/teatree/issues/2887), `AgentHarnessProvider`: `subscription_oauth` | `api_key` | `subscription_then_api_key` | `openai_compatible`, the retired `orca_router_byok` spelling aliased on read), constrained by `AgentHarnessProvider.valid_for(harness)` — `claude_sdk` accepts `subscription_oauth`/`api_key`/`subscription_then_api_key` (the last a plans-first POLICY, not a credential: `agents/credential_policy.resolve_credential_provider` resolves it per dispatch into one of the other two — the metered one only while an uncleared `subscription`-lane `UsageWindowState` carries a plan-exhaustion cause AND a metered key actually resolves — so `_LANE_BY_PROVIDER`, `_provider_child_env` and `t3 cost` never see the composite; a `rate_limit` window is deliberately not an exhaustion cause, and `usage_window_recovery` clearing the window returns the lane to the plans), `pydantic_ai` accepts `openai_compatible` and (#3157 E1b) `anthropic_api` — the latter drives a NATIVE Anthropic Messages-API binding (`PydanticAiBinding.NATIVE_ANTHROPIC`, `pydantic_ai_config.resolve_native_anthropic_model`, one branch in `_resolve_model`) instead of the OpenAI-compatible router client, so real `cache_control` is reachable. **Open harness registry ([#3157](https://github.com/souliane/teatree/issues/3157) E1).** The backend set is no longer a closed enum: `agents/harness_registry` holds a name→`HarnessSpec` registry populated from the `teatree.harnesses` entry-point group (an overlay ships a third transport with ZERO core edits) plus the two built-ins registered at import; `resolve_harness` looks the resolved name up in it and an unregistered name fails loud (`UnknownHarnessError`) at dispatch, not config parse. Each backend declares a typed `HarnessCapabilities` (`hooks`/`mcp`/`cache_control`/`server_resume`/`structured_output`, PLUS the dispatch-lane hints `spawns_cli_child`/`metered_lane` — #3157 AH-5), which `runner.py`'s dispatch reads through the protocol's typed `capabilities` attribute instead of `isinstance`- or untyped-`getattr`-branching on the concrete harness class. A `HarnessSpec` also carries the backend's `valid_providers`, consulted by `resolve_harness` to validate the configured `(agent_harness, agent_harness_provider)` pair (#3157 AH-6 — the open parallel of `AgentHarnessProvider.valid_for`, so an overlay backend's own provider constraint is enforced). Past the `open` boundary a provider-agnostic backend consumes the NEUTRAL `HarnessOptions` (`agents/harness_options`), adapted once from the vendor `ClaudeAgentOptions` at `open` (#3157 AH-2), so the vendor type never threads into pydantic_ai/Vertex logic; the boundary signature stays the vendor type until the deferred SDK port-surface migration. **Context/cache API ([#3157](https://github.com/souliane/teatree/issues/3157) E2).** `src/teatree/agents/context_plan.ContextPlan` is an ordered set of stability-tagged segments (`static`/`per_repo`/`per_task`/`volatile`) with cache boundaries; `cache_control_plan` maps each boundary to a `cache_control` breakpoint (≤4) with a TTL, and the cacheable head is byte-stable (no timestamps/uuids before the last breakpoint, test-enforced). The `ContextPlan` core type ships and is proven through the `teatree.overlay_sdk` surface (for the Factory to build against), but the harness-side application of the breakpoints onto a live request is DEFERRED to the Factory's native-binding option-builder (which will emit pydantic_ai `CachePoint` markers) — the never-fed harness passthrough was removed as dead (#3157 AH-1). `lane_b/compaction.CompactionPolicy` replaces the hardcoded head+tail trim (per-phase `keep_recent`, DB-configurable). That whole-message trim only engages past `keep_recent + 1` messages, so a twenty-turn run is never compacted while every tool result in it is re-sent on every request — the dominant per-request cost on a metered lane. So the phased Agent carries a `ProcessHistory` capability that runs `elide_stale_tool_results` before EACH model request, stubbing the stale `ToolReturnPart` content (DB-home `agent_compaction_keep_tool_results`, default 6 messages, `0` disables). Its boundary advances in steps of `keep_tool_results`, and pydantic_ai writes the processed history back into the run, so consecutive requests between steps share a byte-identical prefix the provider's prefix cache keeps hitting. The stub names the tool, the dropped size and the recovery; the call→return pairing, the tool names and the `tool_call_id`s all survive, so the provider still accepts the history and the pinned head and the turn in flight are never touched. `t3 cost` gains a per-lane/phase cache-hit ratio and flags price-table estimates distinctly from a reported figure (`TaskAttempt.cost_is_estimated`, the metered router's own reported cost passed through when present — #3157 E5). `agent_harness_provider` DEFAULTS TO UNSET (`None`): only an explicit operator pin forces eager credential resolution on a `ClaudeSdkHarness` dispatch — unset inherits the ambient env unchanged, preserving the `claude` CLI's own native auth. Only `ClaudeSdkHarness` spawns the bundled `claude` CLI child and needs an `agent_harness_provider`-keyed Anthropic credential — `PydanticAiHarness` resolves its own OpenAI-compatible credential lazily inside `open` (`teatree.llm.openai_compatible.resolve_openai_compatible_backend`, env `OPENAI_COMPATIBLE_API_KEY`/`OPENAI_COMPATIBLE_BASE_URL` then `pass`; the retired `ORCA_ROUTER_*` vars are reported loud, never read), caught by the same "fail loud, record it" `CredentialError` contract. **Cached-resume parity ([#2886](https://github.com/souliane/teatree/issues/2886)).** `claude_sdk` resumes a parked headless run cheaply via the SDK's own `--resume <session_id>`; the provider-agnostic transport has no server-side session, so `teatree.agents.pydantic_ai_resume` re-homes the same continuation in the harness: when a run ends, BEFORE its outcome is recorded, the live `PydanticAiHarnessSession.history` (`list[ModelMessage]`) is JSON-dumped (`ModelMessagesTypeAdapter`) and stored durably under `Ticket.extra['pydantic_ai_threads']`, keyed by that `Task`'s own pk (single-use — a resume pops its entry) via the locked `Ticket.merge_extra`, so a failure, a limit park and a `needs_user_input` park all leave a conversation the next dispatch can continue; a requeue types the row `self` only once that thread (or, on `claude_sdk`, a server-side session id) exists, and the entry is dropped when the run completed without asking for input or the requeue sweep escalates or retires the row; `resolve_harness(task)` rehydrates it on resume by walking the typed continuation lineage (`session_lineage.resumable_lineage`) exactly like `resume_session_id` does for `claude_sdk`, so both backends land on the same source and an untyped child on either lane starts fresh. Resending the rehydrated history is the whole prompt-cache mechanism (no manual `cache_control` — semantics differ per provider behind OrcaRouter and are opaque to teatree); a cache hit shows non-zero `cache_read_tokens` on the resuming `TaskAttempt`, a miss simply re-pays the context as ordinary input tokens, and the resume never refuses. A refusal BEFORE the harness genuinely opens — a budget breach (checked before `resolve_harness` runs at all) or a failed OrcaRouter credential resolution inside `open` — must never permanently destroy the popped ancestor thread: `resolve_harness` records the popped ancestor as `PydanticAiHarness.resume_source`, and `run_agent`'s `CredentialError` handler restores it via `persist_parked_thread` before returning the failure ([#2916](https://github.com/souliane/teatree/issues/2916)). **Regulated-path model allowlist ([#2887](https://github.com/souliane/teatree/issues/2887)).** A nonempty DB-home `regulated_path_model_allowlist` restricts inference to model IDs matching its compliance-vetted patterns. `PydanticAiHarness._resolve_model` calls `src/teatree/agents/regulated_path.assert_model_allowed_on_regulated_path()` before credential resolution; an empty list imposes no model restriction. The list is an installation value, per overlay, and the gate always applies when it is populated. This is a CLIENT-SIDE check: a router handle can still resolve server-side to a model outside the list, so a hard regulated-path restriction also requires the provider-side allowed-model policy or explicit model IDs. **OrcaRouter dark call-site wiring (ships OFF; `agent_harness` default stays `claude_sdk`, so nothing routes to Orca until an overlay flips `agent_harness=pydantic_ai` AND the wallet is funded).** Four seams complete the binding: **(1) model-id normalization** — teatree's abstract tiers resolve (via `TIER_MODELS`) to Claude DASH-form ids that OrcaRouter's catalog does NOT carry (Orca serves PROVIDER-PREFIXED ids — `anthropic/<dotted-id>`, the open-source pool, named router handles), so `src/teatree/agents/model_tiering.resolve_pydantic_ai_model` normalizes a teatree-native id UP to the OrcaRouter router handle from the SEPARATE `PYDANTIC_AI_TIER_MODELS` catalog (all abstract tiers collapse to one handle — the router's own bandit does the mundane-vs-hard tiering; overridable per tier via the DB-home `agent_pydantic_ai_tier_models` map, and PER-OVERLAY via the DB-home `openai_compatible_model` setting so the per-overlay endpoint/model split is config/overlay-driven, not hardcoded — the override applies only to the normalize-UP branch, so an explicit Orca-native pin still wins), while an explicit Orca-native pin passes through and still hits `assert_model_allowed_on_regulated_path`; **(2) step cap (cheap-model guardrail #1)** — the DB-home `pydantic_ai_request_limit` (default 40 — a real turn budget above the ~16-request Lane-B reality, per-overlay overridable, `0` = uncapped, a positive caller `max_turns` winning over it) becomes a `pydantic_ai` `UsageLimits(request_limit=…)` on every `PydanticAiHarnessSession` run so a cheap-model maker cannot drift on a long tool loop (the FSM chunks work into phases + the orchestrator re-dispatches, so a per-run cap composes with orchestration); **(3) verifier pinned to Claude (cheap-model guardrail #2)** — `src/teatree/agents/model_tiering.PHASE_HARNESS`/`resolve_phase_harness` pin the VERIFICATION phases (`reviewing`/`requesting_review`/`testing`, `VERIFICATION_PHASES`) to `claude_sdk` regardless of the `agent_harness` setting — overridable per-phase via the DB-home `agent_phase_harness` key, an EMPTY override keeping the pinned defaults byte-identical — so when a MAKER phase rides a cheap open-source model the checker in the maker≠checker pipeline stays on the trusted Claude lane (the reliability backstop is a Claude verifier + the test-pass-before-merge keystone gate, never the cheap model checking its own work); **(4) `x-lane` header + key path** — the OrcaRouter provider is built from an `openai.AsyncOpenAI` client carrying a default `x-lane: <factory|eval|bulk>` header whose value is the DB-home `openai_compatible_lane` setting (`factory` default = the headless factory dispatch, `eval` = the eval CI job via `T3_OPENAI_COMPATIBLE_LANE=eval`, `bulk` = a secondary overlay's cheap bulk legs, which a routing rule keying on `headers["x-lane"] == "bulk"` picks up; informational until such a rule matches it), and the DB-home `openai_compatible_credential_entry` points teatree at an existing per-account `pass` entry with NO copy (`OPENAI_COMPATIBLE_API_KEY` env still wins); the DB-home `openai_compatible_extra_headers` map, which carries only the allowlisted `X-OrcaRouter-Include-Cost`/`X-OrcaRouter-Session-Id` (`config/extra_headers.py` — any other header is refused on every write, the `ConfigSetting` manager seam included, and withheld from sending, export and rendering on read, since config is stored and exported in cleartext), rides every request beside `x-lane` (which it can never displace) — the eval runner's too, which builds its client through the same `build_openai_compatible_provider`, and an `OpenAICompatibleLaneConfig` constructed directly refuses an unlisted header as well with `{session}` replaced by the run's session id, minted in `PydanticAiHarness.open` before the provider exists so the router session header and the reported `session_id` are one id — and so is the router binding's stable session id; the client's `UsageTee` response hook (`llm/usage_tee.py`) records each request's float `cost_usd` and `X-Orca-Resolved-Model` that pydantic_ai drops, so every terminal `ResultMessage`, failed turns included, carries the summed router cost, the resolved model and `usage.per_request`, persisted as `TaskAttempt.result["usage_per_request"]`. Each per-request record also keeps OrcaRouter's documented routing headers (`X-Orca-Router`, `X-Orca-Request-Id`, `X-Orca-Session-Tier`, `X-Orca-Fallback-Level`/`-Model`); `_StreamedToolCapture` records every tool call's name, argument keys and argument size (never an argument value, which can hold a credential), output bytes and duration on success and failure alike, persisted as `TaskAttempt.result["tool_calls"]`; and an `EgressBlockedError` the openai client re-raised as a connection failure is unwrapped from the cause chain, so it still reaches the leak-block classifier. All seven OpenAI-compatible DB-home call-site knobs (`openai_compatible_lane`, `openai_compatible_model`, `openai_compatible_base_url`, `pydantic_ai_request_limit`, `openai_compatible_credential_entry`, `openai_compatible_extra_headers`, `agent_harness`/`agent_harness_provider` pair) are resolved SYNCHRONOUSLY in `resolve_harness` (a `get_effective_settings` read from inside the async `open` fails safe to defaults under Django's async-unsafe guard) and threaded through `OpenAICompatibleLaneConfig`. That resolve reads at the dispatched TASK's OVERLAY scope (`get_effective_settings(task.ticket.overlay)`), NOT global/active-only — whether an overlay runs Lane B and its endpoint/credential/cap are per-overlay overridable and a headless dispatch runs per-task, so a per-overlay override for a non-active overlay applies (a task-less `resolve_harness()` keeps the active-overlay resolution). The pydantic_ai lane also carries a binding-AGNOSTIC per-request output ceiling — the DB-home `pydantic_ai_max_tokens` (default 16384, per-overlay overridable, `0` = the binding's own default) is resolved synchronously in `resolve_harness`, carried on `PydanticAiModelConfig` (NOT `OpenAICompatibleLaneConfig`, since it is not endpoint-specific), and merged by `build_model_settings` as the base `max_tokens` `ModelSettings` key on BOTH bindings (router AND native Anthropic); pydantic_ai's Anthropic binding otherwise defaults to 4096, which truncates a long result envelope mid-JSON, so a `'length'` finish reason on the final `ModelResponse` is surfaced by `PydanticAiHarnessSession.receive_response` as an error (`ResultMessage(subtype="error_max_tokens")`) rather than a silently-amputated success. **Enabling later is a config change, not code:** `t3 <overlay> config_setting set agent_harness pydantic_ai --overlay <name>` (+ `agent_harness_provider openai_compatible`), `openai_compatible_base_url` set (or `OPENAI_COMPATIBLE_BASE_URL` in the worker env), and either `OPENAI_COMPATIBLE_API_KEY` exported or `openai_compatible_credential_entry` pointed at the `pass` entry. The teatree factory overlay keeps the `factory` lane; a secondary/regulated overlay flips to its own endpoint with `config_setting set openai_compatible_model <id> --overlay <name>` (+ `openai_compatible_lane bulk` for its cheap bulk legs); the eval CI job sets `T3_OPENAI_COMPATIBLE_LANE=eval` in its env. Reasoning EFFORT is HARNESS-SCOPED (`src/teatree/agents/model_tiering.HARNESS_EFFORT_SCALE`): the shared abstract-tier default (`xhigh`) is valid on both harnesses' vocabularies, but an operator `[agent.tier_effort]` override outside the ACTIVE harness's scale (e.g. `claude_sdk`-only `"max"` reaching a `pydantic_ai` spawn) is dropped, never forwarded. The typed `ResultMessage` maps to a `TaskAttempt` through the shared `attempt_recorder` chokepoint (#2204; the prior `claude -p` subprocess is gone). **Three spend states, two columns ([#4816](https://github.com/souliane/teatree/issues/4816)).** NULL token columns meant BOTH "a pre-turn park billed nothing" (#4164) and "turns ran, spend unreadable", which demand opposite readings — the second is money a metered ledger cannot see. `TaskAttempt.usage_unknown` marks only the second, so NULL-ness still distinguishes the first two and no enum is needed: NOT NULL + `False` is MEASURED, NULL + `False` is NOTHING BILLED, NULL + `True` is SPEND UNKNOWN. It is set by `runner_usage._attempt_usage` when the stream died before its terminal message or turns ran with no provider token keys at all, and by the two crash catches reaching `Task.complete_with_attempt` from an exception that escaped the drive; a provider-reported `0` stays a measurement, and every other caller bills nothing and keeps the default `False`. A heartbeat-driven `LoopWatchdog` interrupts the session on a turn/cost/runtime breach so an in-flight agent flushes its final status ([#997](https://github.com/souliane/teatree/issues/997)); a per-ticket `TicketBudget` caps cost; a `ResultMessage(is_error=True)` naming a usage/weekly limit lands FAILED, never a silent success. **Sub-agent fan-out ceiling (`src/teatree/agents/subagent_ceiling.py`).** The watchdog bounds a run's DURATION, not its fan-out, so a delegation runaway is invisible to a wall clock. `_build_options` arms a per-dispatch `SpawnCeiling` as a `ClaudeAgentOptions` `PreToolUse` hook matched on the SDK tools the `dispatch_subtask` capability grants (derived from `src/teatree/agents/sdk_tool_map.CAPABILITY_TO_SDK_TOOLS`, never a spelled-out tool name), counting delegation calls for the run and refusing the ones past the DB-home `subagent_spawn_ceiling` (default 20, per-overlay overridable, `0` disables the gate — the watchdog's own `0 = disabled` convention). It refuses a SPAWN, never the run: the verdict is a `deny` on the single tool call, so sub-agents already running finish and the parent keeps its context and its remaining turns, with the refusal naming the ceiling and telling it to complete the work in its own loop. Every refusal is loud on four surfaces — the reason the agent reads, a `systemMessage` in the transcript, a `WARNING` log line, and a `refused`/`breached` counter on the instance. The hook is armed on EVERY phase rather than a maintained delegating-phase list; a phase without the grant already carries those tools in `disallowed_tools`, so it is inert there. **Envelope Stop gate (`src/teatree/agents/envelope_stop_gate.py`, [#3905](https://github.com/souliane/teatree/issues/3905)).** The brief teaching the result-envelope contract (`src/teatree/agents/envelope_contract.py`) is the primary control; this is the net under it. `_build_options` arms a per-dispatch `EnvelopeStopGate` as a `ClaudeAgentOptions` `Stop` hook (unioned with the spawn ceiling's `PreToolUse` entry — distinct event keys, so neither shadows the other) that refuses a turn-end whose assistant output carries no envelope the recorder would accept. Without it a run that ends without the envelope is discovered only by `attempt_recorder` — after the turn is over, the context gone, and the whole run re-dispatched from scratch; refusing at `Stop` turns that into one more turn in the same context. It is SATISFIABLE, never a filter: it reuses the recorder's own `runner_result.parse_result` + `result_schema.check_evidence`, so a turn it allows is a turn the recorder accepts and the two cannot disagree about what counts as an envelope, and the agent writing the real envelope is the only thing that clears it — nothing is relaxed and no result is manufactured. It is bounded and FAILS OPEN: at most the DB-home `envelope_stop_gate_refusals` (default 2, per-overlay overridable, `0` disables — the spawn/watchdog `0 = disabled` convention) refusals per run, never a re-refusal of a turn another `Stop` hook already blocked (`stop_hook_active`), inert on the phases `result_schema.ProseSummaryPolicy.accepted` lets end on prose, and "allow" on any unreadable transcript or unexpected error, because a gate that can wedge a dispatch is worse than the failure it guards. **Round ceiling (`src/teatree/agents/round_ceiling.py`).** A task that keeps fixing, re-verifying and pushing into red pipelines renews its lease indefinitely, so a deploy drain can never finish. The heartbeat driver arms a per-dispatch `RoundCeiling` on every runtime: once the run has worked 90 minutes or completed three pushes, the next round start — a `git push` (any global options), `t3 … push` or `verify-gates`, parsed from argv rather than matched as text — ends the run with a hand-off. A harness that takes hooks gets a `Bash` `PreToolUse` matcher that refuses the command and tells the agent to end with `needs_user_input`; a harness without hooks (the codex app-server, which announces each command as it starts, and the metered lane) is watched through its message stream and interrupted as the round starts, and `runner_outcomes` records the run as a `needs_user_input` hand-off, so either way the task parks behind a deferred question. Work inside a round is never cut off, and the wall-clock watchdog stays the backstop for a run that never reaches a boundary. **Per-run turn ceiling (`agent_max_turns`, [#3890](https://github.com/souliane/teatree/issues/3890)).** Cache-read cost on this lane is `turns x context_size` and every turn re-reads the run's context, so the turn count is the multiplier on a dispatch's bill — a dimension the wall-clock `watchdog_max_runtime_seconds` cannot see and `watchdog_max_turns` reads only from COMPLETED `TaskAttempt` totals, never the run in flight. `_build_options` pins the DB-home `agent_max_turns` (default 250, per-overlay overridable, `0` leaves the spawn uncapped — the ceilings' shared escape-hatch convention) onto `ClaudeAgentOptions.max_turns`, the one place the SDK accepts it. The driver names it per dispatch (`headless._turn_ceiling`) rather than letting the builder resolve it unconditionally, because `max_turns` is not lane-neutral: the neutral `HarnessOptions` adapter reads a positive value as the CALLER's explicit cap and lets it win over a backend's own per-run limit, so handing this lane's ceiling to another backend would silently displace `pydantic_ai_request_limit`. A backend that spawns no `claude` CLI child keeps its own ceiling. A cap that silently truncates would trade a runaway for a stranded phase, so reaching it is loud on both surfaces the truncation class already uses: the CLI ends the run with `ResultMessage(subtype="error_max_turns")`, which `_outcome_failure` matches BEFORE the generic error-result branch and records FAILED under a reason naming the turns taken and the setting that moves the ceiling, and `src/teatree/agents/runner_truncation.alert_owner_max_turns_truncation` DMs the owner through the audited `OWNER_ESCALATION` egress — the same shape as the `max_tokens` truncation alert, so a ceiling is raised deliberately rather than a phase quietly returning less than the work. <!-- skill-symbol-ref: teatree.harnesses is an entry-point group name, not an importable module -->

## Cached prefix, account routing and eval-lane isolation

**Native Anthropic cache settings.** The factory native binding and Anthropic eval runner use the same five-minute `cache` setting and opt-in diagnostics. pydantic-ai adds breakpoints to the last tool definition and instructions, then advances one automatic breakpoint with the message history; these normally consume three of four available slots. Missing blocks consume fewer, and excess explicit message breakpoints are trimmed by the provider. A prefix below the chosen model's minimum length produces no cache write or read. Compare `TaskAttempt` cache-read share only for known-usage native attempts with the same model and stable prompt and tools. The separate `ContextPlan` → `CachePoint` path remains deferred to the Factory option-builder.

**Cached-prefix stability on the dispatch lane.** The `claude_sdk` lane sets `exclude_dynamic_sections=True` on its system-prompt preset, moving cwd / git-status / auto-memory churn out of the cached system prefix and into the first user message. Those sections change between dispatches in one worktree, and any change to the prefix invalidates the whole cache entry, so excluding them is what lets consecutive dispatches share a warm prefix. Teatree's OWN append is assembled the same way: `agents.prompt.build_system_context` orders it STABLE-FIRST — the fixed framing and the skill block lead, the per-task `Task ID` / `Ticket` / `# Prior Task Result` trail — so two dispatches in one phase share a byte-identical prefix at least as long as the skill block, matching what the eval lane already does with `SKILL_BUNDLE_FRAMING`. That append is bounded by `MAX_APPEND_BYTES`. With no overlay active, every phase's real context fits it untruncated with headroom (`tests/conformance/test_phase_context_fits_the_budget.py`): `rules` embeds only its ~18 KiB core, which names a `skills/rules/references/*.md` file for each rule's full text, and a lifecycle phase embeds only `rules` plus its lifecycle skill in full. An active overlay's companion skills can push the reviewing context a few KiB over, so truncation is the degrade path: `agents.context_budget` drops whole `##` / `###` sections off the tail (a heading inside a code fence is not a cut point) and names them (`<skill> § <h2> > <h3>`) in a marker that says to load the skill with the Skill tool, rather than keeping a byte prefix, because a byte cut lands mid-sentence. The reach line, the stack skills' required loads, the companion list and the rules core lead the skill block in that order, so a cut sheds skill bodies before any required load or companion skill's name and the lifecycle tail goes first; the same conformance test pins that a 3 KiB overrun of the overlay-active reviewing render keeps review's `## Workflows` and drops under 8 KiB. A block with no section heading (a JSON survey, a prose summary) falls back to the byte prefix, so the bound holds unconditionally. `ClaudeAgentOptions` exposes no `cache_control` surface at all, so breakpoints and a 1h TTL are unreachable from teatree and prefix stability is the only lever available — `ContextPlan`'s cache-breakpoint passthrough stays dormant for that reason rather than by oversight. NO credential (these two plus the `pydantic_ai` `OpenAICompatibleCredential`) carries a built-in default `pass` path: each resolves from its env var or an explicitly-configured per-account entry (`anthropic_oauth_pass_paths` / `anthropic_api_key_pass_paths` / `openai_compatible_credential_entry`) and fails loud naming that setting when unconfigured, never a dead default. The pieces are named provider-neutral (`Credential`/`CredentialSpec`/`CredentialSource`) by design, so the layer later becomes an `LLMBackend.credential` (Claude today, other providers later) with no call-site rework; DI sources keep it unit-testable without touching the real env / `pass`. **Per-account routing (experimental).** A credential's `pass_path` is not fixed: `teatree.credential_config` reads a per-overlay ORDERED LIST of candidate `pass` entries (config keys `anthropic_oauth_pass_paths` / `anthropic_api_key_pass_paths`, overlay scope then global) and its `PassPathSelector` RANKS the non-exhausted candidates on remaining headroom and injects the RICHEST account's `pass_path` into the credential. The ranking is one implementation — the foundation leaf `teatree.account_headroom` (binding headroom, then weighted 0.4/0.6, then input order, then name), which `teatree.ci_oauth_switch` and the Django-free `teatree.eval.oauth_selection` also call rather than replicate. A candidate with no FRESH measured row is not ranked (there is nothing to rank it on and a fabricated zero would be a lie): it is offered only when NO candidate has one, in the operator's declared list order, so ranking never turns selection into a probe sweep. Account health is a cached probe: the FOUNDATION reader `teatree.llm.rate_limits.read_rate_limits` does one tiny `POST /v1/messages` (the pinned probe model, `max_tokens=1`; an OAuth probe also carries the Claude Code system prompt, without which a subscription token is answered with a bare 429) and folds the account's unified 5h/7d rate-limit response headers (a 200 AND a 429 both carry them) into a token-free snapshot — an answer carrying no unified header raises `RateLimitProbeError`, so every caller reads it as unreachable rather than healthy (a **metered API key** is probed differently — `read_api_key_status` with `x-api-key`, no `Bearer`/oauth beta: it emits no unified windows, so a funded 200 yields its per-minute `requests`/`tokens` remaining and an out-of-credits 400 "credit balance is too low" yields a depleted credit state mapped onto the same exhaustion signal so routing refuses a dead key — the exact prepaid $ balance is not available via a standard key); the DOMAIN `AnthropicTokenUsage` cache stores each account's utilization/status/reset keyed by `pass_path`, with `is_exhausted` = either window at its limit (5h≥95 % / 7d≥99 %) or rejected, and `anthropic-ratelimit-unified-representative-claim` attributing an account-wide `rejected` verdict to the window Anthropic calls binding; `valid_until` keeps a healthy verdict for a short TTL and an exhausted one until its blocking window resets — unless the verdict is UNVERIFIED (synthesized because the account could not be probed), which is capped at the TTL so a wrong window or a wrong account self-corrects in minutes. A row also records a `token_fingerprint` (a hash of the token it was PROBED with), because `valid_until` alone outlives a rotation of the credential at that `pass_path`: an exhausted verdict is trusted for days, so a `/login` to a fresh account left the whole factory denied on the previous account's exhaustion. So `t3 tokens` always re-probes every account live (`--cached` renders the stored verdict instead), and the `/login` recovery (`teatree.core.account_switch`) expires every cached verdict so the governor stops denying on the old account. The selector and `read_quota_signal` stay cache-only and read no secret to route. The selector is STICKY (an `AnthropicActivePick` pointer per `(kind, scope)`): the HOT path reuses a fresh, non-exhausted pick from the CACHE with NO network, but only while that pick is ALSO outside the WARNING band (`WARNING_5H` 0.80 / `WARNING_7D` 0.90 — thresholds that already existed below the exhaustion limits so a warning precedes exhaustion, and which now live beside those limits in `anthropic_token_usage` because a routing consumer may not import the display layer). Sticky is what preserves the warm prompt-cache prefix, so a HEALTHY pin is reused with no comparison at all; once the pinned account reads WARNING the selector re-ranks and moves. Without that band a pin sat indefinitely on an account at 98 % weekly — not exhausted, so never reconsidered — while an idle account went unused; it only re-probes on a cache miss/expiry, and only then falls back across overlays, raising `AllTokensExhaustedError` (a loud `CredentialError`) naming the earliest reset when every configured account is spent. The pointer is per-scope, so a spent account would otherwise strand every OTHER scope pinned to it until each took its own miss: recording a reading EXHAUSTED (`AnthropicTokenUsageManager.record` — the one place the reactive writer and the operator's `t3 tokens` probe converge, so no future writer can forget it) UNPINS that account from every `(kind, scope)`, and each scope then re-selects from its own list. Exhaustion is the only verdict provably wrong for every scope at once, so WARNING never unpins — it stays a per-scope re-rank trigger. The dash health-band panel names the scopes currently routed to each account, so a pin stranded on a spent one is visible in the browser rather than only in the database. `runner.py` passes the task's ticket overlay as `scope`; metered/eval consumers stay GLOBAL scope. The operator-facing **`t3 tokens`** reporter (`teatree.token_report`) is the read-side diagnostic over this same state: it enumerates every configured `pass` entry (the per-overlay OAuth + API-key lists plus global), ALWAYS probes each one concurrently (a cached row is NEVER rendered by the default path — it can be stale in every field; `--cached` is the opt-in inverse that renders the routing verdict and probes nothing), and renders each account's health per credential kind, best account first — an OAuth row shows org id + 5h/weekly utilization + extra-usage (overage) balance + 5h/weekly reset + status (healthy / warning / exhausted / missing / unreachable / uncached), with an unreported window rendering `—` rather than `0 %`; an API-key row shows its credit state (healthy when funded / out-of-credits when depleted) + per-minute requests/tokens remaining (not weekly utilization, and no $ balance) — never emitting a token. An ad-hoc token with no `pass` entry can be probed through the REPEATABLE `--token` option (`t3 tokens --token A --token B`): each renders one extra row labelled `token[1]`, `token[2]`, …, its kind auto-detected from the `sk-ant-oat01` / `sk-ant-api03` prefix, probed fresh and NEVER read from or written to the `pass_path`-keyed `AnthropicTokenUsage` cache. The same command carries the routing VERB rather than a report: **`t3 tokens --pick`** resolves a scope's OAuth account through that identical selector, PINS it (so a following dispatch shares the account and its warm prefix) and prints that account's `pass` ENTRY PATH — never a token — on stdout, which is what lets an interactive session ride the per-account routing a dispatched agent gets automatically (`CLAUDE_CODE_OAUTH_TOKEN="$(pass show "$(t3 tokens --pick)")" claude`). The row/JSON identity key is `account` (not `pass_path`) with a `source` (`pass` | `token`) discriminator; a token passed as a CLI option is visible in `ps aux` and shell history, inherent to the option interface. Its FIRST applied rule is the `agent_harness_provider`-selected eval-credential policy below. **Metered-lane auth + isolation ([#2884](https://github.com/souliane/teatree/issues/2884)).** The `sdk` lane authenticates on the credential `agent_harness_provider` selects — DEFAULT the subscription `CLAUDE_CODE_OAUTH_TOKEN` (no per-token bill, so the lane is right-sized — a single effort tier, a smaller trial count, per-account OAuth routing — to stay inside the plan's depleting 5h/7d usage window), with the metered `ANTHROPIC_API_KEY` selectable per run via `t3 eval run --credential api_key` (e.g. for a lane that needs per-token cost accounting). The in-container run recovers the same credential kind from the ONE credential var the host forwards, so no credential knob travels into the container. `make_runner(API_BACKEND, …)` is the single resolution chokepoint (`resolve_eval_credential().export()` — fail loud before the runner exists, export the selected credential for the docker `-e` pass-through); `isolated_claude_env` **strips** the OTHER credential from the child env using the same credential's `spec.conflicting_vars` (the bundled CLI prefers the selected credential only when its conflicting one is absent, so stripping it is what stops the SDK authenticating with the wrong credential). The lane runs **in a container, never on the host** (`--docker` → `dev/Dockerfile.test`, which ships the `claude` CLI; the selected credential is forwarded via docker `-e` pass-through, never argv/logs). The runner and judge run **virgin** (`isolated_claude_env` + clean-room `ClaudeAgentOptions`: `setting_sources=[]`, empty `settings`, a neutral `HOME`/cwd) so the developer's `CLAUDE.md`, auto-memory, and project config never bias a result. **Prompt caching** stays on by the bundled CLI's content-based default (5-min TTL; the API-key switch does not disable it — confirmed via the `cache_creation_input_tokens`/`cache_read_input_tokens` usage fields the harness already surfaces). The stable `SKILL_BUNDLE_FRAMING` leads the system prompt and the polluted preamble lives in the USER prompt, so the cacheable prefix is already maximal; `ClaudeAgentOptions` exposes no 1h-TTL knob, so teatree injects none (no raw `cache_control` headers). **Sub-agent-spawning isolation ([#2642](https://github.com/souliane/teatree/issues/2642)).** A spawning scenario (`scenario_exposes_subagent_spawn` — `orchestrator_delegates_*`, `full_speed_*`, `team_mate_*`, `delegates_under_load_*`) makes the SDK sub-agent do REAL, destructive git work; a neutral cwd does NOT protect the developer's clone, because the sub-agent locates it via the editable install's `.pth` (`import teatree` → real `src/teatree`) and the shared `.git`. So `ApiInProcessRunner._resolve_eval_target` runs each spawning scenario against a per-run EPHEMERAL CHECKOUT (`teatree.eval.ephemeral_checkout`): a throwaway `git worktree --detach` whose own working tree + detached `HEAD` absorb every write, with `cwd` + `add_dirs` pointed at it and `ephemeral_checkout_env` overlaying `PYTHONPATH` (so `import teatree` resolves into the throwaway) and clearing the inherited `GIT_*` pins (so `git` rediscovers from the ephemeral cwd). The checkout is torn down after the run; a non-spawning scenario keeps the existing clean-room shape unchanged. When the real root cannot be located the spawning scenario REFUSES (`EphemeralCheckoutError`) rather than fall back to the real clone. **Transient missing CLI ([#2642](https://github.com/souliane/teatree/issues/2642)).** `shutil.which("claude")` momentarily returns `None` when the bundled CLI auto-updates mid-run (the nvm symlink is swapped); `resolve_claude_path` re-probes with a bounded backoff so one transient miss never reds the rest of the batch, while a genuinely-absent binary still fails after the bounded attempts. **All-skipped guard ([#1811](https://github.com/souliane/teatree/issues/1811)).** A run that never happened (`claude` absent/unauthenticated) would SKIP as passed; `--require-executed` exits non-zero when `collected > 0` but `executed == 0`. The standalone metered workflow (`.github/workflows/eval.yml`, weekly cron + manual) passes `--require-executed` unconditionally (never key-gated) and is no-PR-guarded so a window with nothing merged skips cleanly. **Freshest-account pre-eval selection.** When the CI secret `EVAL_OAUTH_TOKENS` holds several subscription tokens (newline-separated), a pre-eval step (`scripts/eval/select_oauth.py` over the Django-free `teatree.eval.oauth_selection`) probes each token's remaining 5h/7d headroom through the same `read_rate_limits` header probe, ranks them by binding-then-weighted headroom (mirroring `teatree.ci_oauth_switch`, deterministic first on a tie), and exports the freshest as a masked `CLAUDE_CODE_OAUTH_TOKEN` into `$GITHUB_ENV` for that run — so a full fan-out never lands every leg on one throttled window. The step OWNS the credential decision (it also exports `T3_AGENT_HARNESS_PROVIDER`) and is backward-safe: an unset `EVAL_OAUTH_TOKENS` passes the single `CLAUDE_CODE_OAUTH_TOKEN` secret through unchanged. When every candidate is exhausted the step fails loud, unless the opt-in `EVAL_API_KEY_FALLBACK` repo variable (default off) flips the run to the metered `ANTHROPIC_API_KEY`. Wired into `eval.yml`, `eval-pr.yml`, `eval-nightly.yml`, and `eval-weekly-reusable.yml`. This is the per-run, in-CI complement to the host-side `t3 eval ci-account switch` (`teatree.ci_oauth_switch`), which points the single `CLAUDE_CODE_OAUTH_TOKEN` secret at the healthiest `pass`-stored account ahead of time.
